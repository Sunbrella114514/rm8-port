# 掷骰与棋盘回合流程（移植规格）

> 目的：让移植版（`port/app/roles.cpp`，C++ + librw）按原版逐帧重现掷骰、走路、停下、回合交接；并说明 C++ 流程在哪里调用 Python 2.4 原版脚本、Python 又通过什么回到 C++。
> 依据：`out/final_v2/RichMan8_named.c`（函数名只作索引，结论都按代码判断）+ 反汇编（`scripts/exe_dis.py`）+ 运行中原版的只读内存（`scripts/game_turn.py`）。
> 置信度：**[V]** 已核对代码或反汇编，或已用实机内存验证；**[H]** 代码证据强，但含义是推断的；**[M]** 只读了部分代码，或含义仍不确定。函数地址写作 `@0x…`。
> 本文新增的辅助脚本：`scripts/fnv2.py`（打印 final_v2 反编译函数和调用者）、`scripts/consts.py`（读 exe 常量）、`scripts/game_turn.py`（只读运行中游戏的回合与骰子状态）、`scripts/art_info.py`（查 role.bin 的 art id）、`scripts/this_calls.py`（列出以某全局对象为 this 的调用）、`scripts/which_fn.py`（地址 → 所在函数）。

## 1. 骰子

### 1.1 资源 [V]
- **骰子面贴图**：`CDice__ctor_dtor13 @0x47c9e0` 读取 `texture\dice\dice_1..6.tga`，存入贴图表 `*(0x63fba8)` 的槽 0..5。
- **滚动帧贴图**：同一函数读取 `texture\dice\animation\dice_a0..a5.tga`，存入槽 6..11。
- 以上 12 张图都是 128×128、32 位（tex0000.dat 中每张 65580 字节）。
- **骰子不是 3D 模型**，而是一张贴图的 Im3D 四边形（见 1.4）。
- **步数数字**：`CDice_LoadNumberTexture @0x47cc90` 读取 `texture\font\number.tga`（128×128）。它是 4 列 × 3 行的图集，每格 32×42 像素：
  - 字符表在 0x5e1ac0，按行排列为 `"0123" "4567" "89* "`；
  - 第 c 列第 r 行的格子矩形为 (32c, 42r, 32, 42)（`SpriteSheet_Load @0x417690`）。

### 1.2 骰子对象（角色 +0x22C 起）与骰子数 [V]

| 偏移（相对 +0x22C） | 含义 |
|---|---|
| +0x00 | 最大骰子数 = 交通工具（1 步行、2 机车、3 汽车） |
| +0x04 | 本次骰子数（角色 +0x230） |
| +0x08 | 上一次骰子数 |
| +0x10..+0x18 | 3 个骰子槽开关 |
| +0x1C..+0x24 | 槽开关备份 |
| +0x28 | 滚动帧号 0..17 |
| +0x2C | 抛出前计时（秒） |
| +0x30 | 指定点数（1..6 有效） |
| +0x34..+0x3C | 掷骰原点 = 角色位置 |
| +0x40..+0x48 | dicePos（x 已按朝向翻转） |
| +0x4C / +0x58 | 骰子数组 / 个数 |

各函数的作用：
- **`SetMax(n) @0x47d930`**：在 1 ≤ n < 4 时执行，把最大骰子数和本次骰子数都设为 n；前 n 个槽开关设为 1，其余设为 0。由 `Role_SetTrfTool @0x48a0c0` 和 `Role_InitState @0x480d30` 调用。
- **`Dice_SetCount(n) @0x47da00`**：在 n ≤ 最大骰子数时执行，先把当前数存为“上一次”、备份槽开关，再设为 n 个骰子。
- **`State_SyncFields @0x47d9c0`**：在“单骰场景”（状态 4）结束后恢复原来的骰子数。
- **电脑**：`Role_BeforeRollDice @0x484c80` 调用 Python 的 `DiceNum`（`AI_AskDiceNum @0x4fc120` = `AI_CallScript(7,0)`），返回值在 1..最大骰子数之间才执行 `Dice_SetCount`。
- **玩家**：在骰子界面里通过 `Role_CycleDiceCount @0x48a210` 和 `Role_ToggleDiceSlot @0x48a1c0` 选择骰子数；界面由 `Role_OnBeforeDice @0x4813c0` 刷新。

### 1.3 开始掷骰 `Role_StartRollDice(force) @0x484e50` [V]

1. **乌龟**：若乌龟天数（+0x1CC）> 0 且 force == 0，则乌龟天数减 1，并令 force = 1（即只掷 1 个骰子，点数固定为 1）。
2. **镜头**：调用 `Camera_SetFocusPoint(角色位置)`，镜头瞬间对准角色（见 3.3）；同时清除提示文字。
3. **骰子偏移**：
   - 取 dicePos = roleinfo `+0x350 + (本次骰子数 − 1) × 12`（3 个 float）。注意下标是**骰子数**，不是交通工具；16 个角色的 3 组 dicePos 都是 (−10, 30, 55)。
   - 朝向模型 `+0x04 % 3 != 0`（即 fr、br）时，x 乘以 −1。
   - 结果按 float 原样写入 +0x26C..+0x274；反汇编确认没有取整。
4. **布置骰子场景**：调用 `Dice_SetupScene(角色位置, force) @0x47d4d0`，然后：
   - 状态 = 3；
   - 调用 `vf5(1,1,0)`，播放掷骰动作 1 次；
   - 清空消息队列；
   - 隐藏鼠标光标。

**其他入口**：
- 消息 0x1A：`Role_StartRollDice(a)`。Python 的 `Role.Go(role, n)`（`py_Role_Go @0x4fe510`，遥控骰子卡）发出的就是这条消息，n 即为指定点数。[V]
- 玩家：在状态 6 下点骰子按钮，`Game_TriggerRollDice @0x4e8340` 调用 `Role_StartRollDice(0)`。[V]
- **单骰场景** `Role_StartDiceSceneCount1 @0x484d70`：由点券中心、饭店访客等界面在状态 9 时调用。它固定使用 1 个骰子和 dicePos1，状态 = 4；结束时调用 `u_CPlayerTag_SyncGameState @0x485020`：恢复骰子数，`vf5(2,0,0)`，状态 = 9，并以 `(点数, 1)` 调用 `g_GameState` 的虚函数 +0x30 把点数交给界面。[V]

### 1.4 骰子几何 [V]

每个骰子是一个 0xF8 字节的对象（`Dice_InitLayout @0x47c450`），各字段如下：

| 偏移 | 内容 |
|---|---|
| +0x00 | 滚动帧计数 0..5 |
| +0x04 | 当前贴图 |
| +0x08 | 4×4 的 RwMatrix |
| +0x48 | 4 个 Im3D 顶点（每个 0x24 字节） |
| +0xD8 | 起点 |
| +0xE4 | 终点 |
| +0xF0 | 基准高 |
| +0xF4 | 点数 |

**顶点**：第 k 个顶点（k = 0..3）的位置为 (25 − 50·(k&1), 25 − 50·(k/2), 0)，颜色 0xFFFFFFFF，UV 为 (k&1, k/2)。也就是 50×50 的方块，以三角带方式绘制。

**绘制** `Dice_DrawAllEffects @0x47d340` / `Dice_DrawEffect @0x47c8e0`：
- 渲染状态：关闭 Z 测试（renderstate 6 = 0）、关闭 Z 写入（8 = 0）、不剔除（CULLMODE = 1），画完恢复为 1 / 1 / 2。
- 调用 `RwIm3DTransform(顶点, 4, 矩阵, 0x19 = UV|XYZ|RGBA)` 后按三角带（tristrip）绘制。

**朝向**：
- 先绕 X 轴转 pitch（40°），再绕 Y 轴转 yaw（135°）。
- 转完后四边形法线 = 镜头 at 向量 (0.54, −0.64, −0.54)，即一张始终正对镜头的公告板。
- RW 镜头的 right 向量指向屏幕左侧（实机 right = (−0.707, 0, −0.707)，与 at×up 方向相反），所以 +x 的顶点在屏幕左边、u = 0，贴图不镜像。

**两个阶段使用不同的矩阵**：

| 阶段 | 函数 | 矩阵构成 | 显示大小 |
|---|---|---|---|
| 手持阶段 | `Dice_RandomizeState @0x47c540` | 缩放 0.8（REPLACE）→ 旋转 pitch → 旋转 yaw → 平移到手持位置 | 40×40 |
| 滚动阶段 | `Dice_UpdateAnimation @0x47c730` | 旋转（REPLACE，不缩放）→ 平移 | 50×50 |

### 1.5 动画时间线（`Dice_UpdateRoll @0x47d090`，状态 3/4 每帧调用一次）[V]

时间 dt 为游戏秒，状态 3 时不乘游戏速度。

**阶段 A：手持（0.3 s）**
- `Dice_SetupScene` 只创建 1 个骰子，位置为 `(P.x + dicePos.x', P.y + dicePos.y, P.z)`；其中 P 是角色位置，dicePos.z 不加在这里。
- 贴图是随机的滚动帧：`rand()%6 + 6`。
- 抛出前计时 +0x2C = 0.3。
- `Dice_UpdateRollPhase1 @0x47d210`：
  - 每帧计时减 dt；
  - 计时仍 > 0 时，把这个骰子沿 y 移动 `−10·dt`（共下沉约 3 个单位）；
  - 代码里另有一支 `(elapsed·100 + 20)·dt` 的上抛分支，但条件 elapsed < 0.5 恒成立，这一支永远不会执行。
- 角色同时在播放掷骰动作（动作 1）。

**阶段 B：抛出（`Dice_BeginRoll @0x47d5c0`，计时 ≤ 0 的那一帧）**
1. 删除手持骰子；帧号 +0x28 = 0。
2. 骰子数 N = 本次骰子数；若指定点数在 1..6 之间，则 N = 1。
3. 取 F = normalize(at.x, 0, at.z)（镜头水平前向），R = 镜头 right 向量（镜头帧 +0x10）。
4. 每个骰子 i（从 0 开始）：
   - 起点 = P − 2i·F；
   - 终点 = P + off[i]·R − (100 + 2i)·F；
   - off：1 或 3 个骰子时为 {0, 50, −50}，2 个骰子时为 {25, −25}。
   - 由于 R 指向屏幕左侧，第 1 个骰子飞向左、第 2 个飞向右；所有骰子都向镜头方向飞 100。
5. `Dice_SetupRoll @0x47c630`：
   - 点数 +0xF4 = `rand()%6 + 1`（指定点数时之后被覆盖）；
   - 帧计数 = `rand()%6`；
   - 基准高 +0xF0 = dicePos.z（55）。

**阶段 C：滚动**
- dt 累加到全局 `0x63fbb0`（这个全局在两次掷骰之间不清零）。
- 每当累计 ≥ 0.04 s：
  - n = ftol(累计 / 0.04)；
  - 帧号 += max(n, 1)，上限 17；
  - 累计 −= n·0.04；
  - 然后对每个骰子调用 `Dice_UpdateAnimation(帧号)`。

`Dice_UpdateAnimation(f)` 的计算：
- 帧计数 = (帧计数 + 1) % 6；f < 16 时贴图 = 滚动帧 a[帧计数]，f ≥ 16 时贴图 = 点数面 dice_[点数]。
- t = f / 16（f = 17 时 t = 1.0625，会略微越过终点）。
- x、z = 起点 + (终点 − 起点)·t。
- **y = 高度表[f] + 基准高 − 100**。这是世界坐标的**绝对高度**，与起点、终点的 y 无关。
- 高度表在 0x5e19f0：`130,160,185,205,220,230,235,220,205,180,145,100,50,60,65,60,50,50`。
  - 当 dicePos.z = 55 时，y 依次为：85、115 … 190（f = 6 时最高）… 5（f = 12 第一次落地）、15、20、15、5、5（小幅弹起后落定）。
- 第一次更新时帧号已 ≥ 1，所以 f = 0 那一格不会显示。
- 正常帧率下共 17 步 × 0.04 s = 0.68 s。

**音效**：帧号恰好等于 12 那一刻（且音频管理器 `*(0x61adf8)` 存在时）调用 `CAudioMgr_PlaySample(9, 0,0,0, 1000.0, 0, 1.0, 1)`，即样本 9，播放 1 次。如果帧号一次跳过了 12，就不会响。

**阶段 D：停留（`Dice_FinishRoll @0x47d410`）**
- 帧号 ≥ 17 之后，dt 累加到全局 `0x63fbb4`，满 1.0 s 时：
  - 结果 = 所有骰子点数之和；
  - 删除骰子；
  - 清零该累加器。
- 未满 1.0 s 时返回 0。

**交接**：
- 状态 3：主循环每帧调用 `vf26(返回值)`，即 `CPlayerTag__BeginMoveSteps @0x484f90`；该函数忽略 ≤ 0 的值，所以结果出来的那一帧才开始走路。
- 状态 4：结果交给 `u_CPlayerTag_SyncGameState`（见 1.3）。

**总时长**（正常帧率）：0.3 + 0.68 + 1.0 ≈ 1.98 s。

### 1.6 骰子何时画、画在哪一层 [V]

场景渲染顺序（`@0x4a1a80`）：
1. 地图与摆件（第 0 遍）；
2. NPC；
3. 角色（`@0x495bf0`）；
4. 水面；
5. 粒子；
6. 摆件第 1 / 3 遍；
7. **当前角色的骰子**（`Game_UpdateCurrentRole @0x495dd0` → `Dice_DrawIfActive @0x485fd0`）；
8. 无 Z 写入的角色附件。

骰子画在两处：
- **角色渲染里**：`CPlayerTag__Render @0x485d00` 中，若状态 == 3、朝向为背面（模型 2/3，`+4/2 != 0`）且手持计时 > 0，则在**画角色之前**画骰子。由于骰子不写 Z，角色会把它挡住，看起来像拿在身后的手里。
- **场景最后**：`Dice_DrawIfActive` 在状态为 3 或 4，且“朝向为正面，或手持计时 ≤ 0”时画骰子。此时 3D 内容已全部画完，骰子显示在所有物体之上。

### 1.7 步数数字（走路时）`CDice_DrawNumber(n) @0x47cef0` [V]

- **何时画**：`CPlayerTag__Render` 在状态 == 1（走路）时每帧调用，n = 剩余步数 +0x3C。这是唯一的“步数计数器”。
- **画法**：它是 **2D 屏幕叠加**（Im2D），不是挂在头顶的 3D 物体。
- **位置**（左上角，屏幕像素）：
  - x = ftol(W/2) − 16（个位数）或 − 32（两位数），即水平居中；
  - y = ftol(H/2 − init.txt 宽度 / 1024 × 230)；800 宽时约为 H/2 − 180。
  - W、H 取镜头光栅尺寸（`@0x41d9c0` / `@0x41da00`）；“init.txt 宽度”是 `InitTxt_GetParam(1)`。
  - 因为镜头总是对准走路的角色（3.3），数字正好落在角色头顶上方。
- **外观**：
  - 字符串由 `swprintf(L"%d", n)` 生成；
  - `Render_DrawSpriteSequence @0x417330` 按字符逐个画 32×42 的四边形，缩放 1.0，字间距 0；
  - 顶点颜色来自 0x6044e8 的字节 (FF,FF,FF,FF)，即不染色、不透明；
  - 采样器 MIN/MAG 临时设为 POINT（画完恢复为 LINEAR）。
- **停止**：停下后状态离开 1，数字就不再画。
- **相关但不同的东西**：定时炸弹（+0x288，`Billboard_RenderWithNumber @0x499ef0`）是在角色头上的 3D 公告板，带两位数倒计时，每经过一个道路点减 1（`@0x485a20`）[H]。

## 2. 回合状态机

### 2.1 驱动方式 [V]

**每帧更新** `CPlayerTag__vf3_Update @0x481500`（每个角色都调用）：
1. 破产（+0x1B4 == 7）的角色什么都不做。
2. **镜头忙**（`*(0x61ae00)` 的 +0x20、+0x2C、+0x38 任一非 0）时，跳过第 3~5 步，只更新动画。
3. 状态 == 1 时，dt 乘以 `(init.txt speed − 1) / 4 + 1`。乘过的 dt 也用于动画，所以走路动作同样变快。
4. 同格错开补间 `vf28 @0x4818d0` 若在进行中（返回 1），本帧到此为止。
5. 转身 `vf12`（`Anim_RotateSmooth @0x47bcd0`）若在进行中，本帧到此为止。
6. 否则执行状态机 `CPlayerTag__vf3_Main @0x481bc0`。

**消息队列**：
- `Role_EnqueueMsg(cmd, a, b) @0x484890`：追加到队尾。
- `Role_EnqueueMsgAt(pos, …) @0x484930`：插入到指定位置（0 = 队首）。
- 状态 8 时，`Role_DispatchQueuedMsg @0x481df0` **每帧只取一条**处理。
- 处理函数常把状态改成 1、3、5、9、10 等；那些状态结束后再回到 8，继续取下一条。

### 2.2 状态值（+0x1B8，`@0x481bc0`）[V]

| 值 | 含义 | 每帧调用 | 怎样离开 |
|---|---|---|---|
| 0 | 不在行动（非当前角色）/ 空闲 | `Role_TickIdleAnim @0x48a3f0`：+0x1B4 == 0 且 +0x5C == 0 时，每隔 `rand()%10 + 10` 秒播放 1 次动作 3，播完由回调 `@0x4806f0` → `@0x48a330` 切回动作 2 | `Game_TurnNextRole` 把新当前角色从 0 改为 8 |
| 1 | 走路 | `Role_StepAlongPath @0x485860`（第 2.4 节） | 步数走完时由 vf19 改为 8 |
| 3 | 掷骰 | `Dice_UpdateRoll` → `vf26(结果)` | `BeginMoveSteps` 改为 1 |
| 4 | 单骰场景（界面用） | `Dice_UpdateRoll` → `u_CPlayerTag_SyncGameState` | 改为 9 |
| 5 | 等待 +0x1E8 秒 | `Role_TickWaitTimer @0x4850b0` | 计时到 0 且附属特效结束后调用回调，改为 8 |
| 6 | **等玩家操作**（可用卡、选骰子数、点掷骰按钮；回合箭头只在此状态显示） | `Role_TickIdleAnim` | 界面调用 `Role_StartRollDice` 改为 3，或用卡后改为 8 |
| 7 | 模态界面 | `Role_CloseModalUi @0x4889b0`（把界面结果写回队列中 b == 0x80000000 的消息） | 8 |
| 8 | **分发消息** | 队列为空时：调用 `Role_CheckMissionsByCharacter`，入队 `0x65(60)` 等待 1 秒，再入队 `0x66` 结束回合 | — |
| 9 | 外部事件进行中（事件界面、NPC、剧情） | 无 | 外部调用 `Role_UpdateStatusTransition @0x4860d0` 改为 8 |
| 10 | NPC 互动中 | 无 | `Role_LeaveState10 @0x486110` 改为 8 |
| 11 / 12 | 走向建筑 / 地块 | `@0x4854b0` / `@0x4856d0` | — |
| 13 / 14 | 动画片段（movie clip）+ 等待 | — | 等待结束改为 8 |
| 其它 | — | 立即改为 8 | — |

**等待时长**：
- `Role_BeginWaitSeconds(s) @0x485080` → `@0x47b3b0`：实际等待 = `s × (1 − min((init.txt speed − 1) / 10, 1))`。例如 speed = 4 时，1 秒只等 0.7 秒。
- 消息 0x65 的参数是帧数，除以 60 换成秒。`Role_GetWaitFrames @0x485150`：1 → 180，2 → 60，其它 → 30。

### 2.3 一个回合的完整流程（普通状态的角色）[V]，除非另注

1. **换人**：`Role_SkipTurnToNextRole @0x4830e0`（由消息 0x66 触发）：本角色状态 = 0，隐藏光标，然后调用 `Game_TurnNextRole @0x4971a0`：
   - 座位号 +1，循环；跳过空位和破产者。
   - 绕回 0 号座位时，若有人类玩家且总人数 > 1，调用 `Game_OnTurnStart(1)`（新一天）和 `Game_FindLeaderByWinCondition`。[M] 这两个函数的细节未展开。
   - 若新角色带有错开偏移：调用 `Role_CheckPathValid`，补间回到中心、比例 1.0；并以 `Game_MoveRoleToPosition(node, 位置 − 偏移, 1)` 把同格的其他人挤开（第 4 节）。
   - 回合箭头移到 `新角色道路点 + (0, 10, 0)`（第 3.1 节）。
   - 刷新界面；新角色入队 `0x68`；若其状态为 0，改为 8；`g_RoleMgr[0xc]` = 当前座位。
2. **消息 0x68**：`Role_LeaveStatus8 @0x483540`：
   - 身份状态 == 8 的特殊情况走单独分支；
   - 一般情况入队 `0x67(0)`。
3. **消息 0x67(step)**：`Role_RunTurnStartStep @0x4842f0`，每完成一步入队下一步：

   | step | 动作 |
   |---|---|
   | 0 | 镜头对准角色；刷新界面与卡片栏；+0x1E4 减 1 |
   | 1 | 把 +0x5E0 中的延迟消息移进队列 |
   | 2 | 闯关剧情 `Role_RunStoryScriptEvents @0x483f40`（C++，不是 Python）+ 任务检查 |
   | 3 | 调用 vf33（空实现） |
   | 4 | 处理事件显示计数 |
   | 5 | 贷款到期 `@0x483170` |
   | 6 | 附身到期 `@0x483350` |
   | 9 | 按身份状态分派（见下） |

   **step 9** 的分派：
   - 正常状态：
     - 若停留标志（+0x1D0）为 0 且附身糊涂神（6）：`Role_ShowSleepwalkAndRoll @0x48b140`，显示提示并入队 `0x1a(0)` 自动掷骰。
     - 否则：状态 = 8，入队 `0x25(1)`。
   - 冬眠 / 饭店 / 医院 / 监狱 / 消失：分别调用各自的倒计时函数（通常跳过本回合）。
4. **消息 0x25(a)**：`Role_StayOrBeforeRoll @0x484610`：
   - **停留一回合**（+0x1D0）：清除标志，提示 str563；附身糊涂神时入队 `0x12(当前点)`，否则入队 `0x1d(当前点)`，直接触发当前格的事件。
   - **电脑**（+0x1B0），a != 0 时：
     - a == 1 时先做股市操作 `AI_StockTrading @0x4f9310`（Python 的 SSellAll/SSell/SBuy/SBuySum）；若做了，入队 `0x25(2)` 〔string.bin#1827〕。
     - 然后用卡计划 `AI_PlanCardActions @0x4f9670` 和 `Role_UseSpecialCard`；若用了卡，状态 = 8。
   - 其余情况调用 `Role_BeforeRollDice(a)`。
5. **`Role_BeforeRollDice @0x484c80`**：
   - 任务检查返回非 0 时，入队 `100`，稍后重试。
   - 附身糊涂神：自动掷骰（同上）。
   - **人类玩家**：状态 = 6，显示光标，`Role_OnBeforeDice` 打开骰子界面，等待玩家操作。
   - **电脑**：
     - `Role_UseCardBeforeRoll @0x4fbab0` 若用了卡：入队 `99(槽)` 和 `3(槽, 目标)`，状态 = 8。卡片效果执行完后，Python 用 `Role.Settle` 或 `Role.Wait` 发出 `0x25` 或 `100` 回到这里。
     - 否则调用 Python 的 `DiceNum`，再 `Role_StartRollDice(0)`。
6. **掷骰**：状态 3，见第 1 节。
7. **开始走**：`CPlayerTag__BeginMoveSteps(n) @0x484f90`：
   - 剩余步数 = n，状态 = 1；
   - `vf5(0,0,0)`：走路动作循环；
   - n == 18 时 +0x5CC = 1（3 个骰子都是 6）；
   - `vf20(wlk)` 播放走路音效（第 5 节）。
8. **走路**：状态 1，见第 2.4 节。
9. **停下**：vf17 走完最后一步时调用 `vf19 = CPlayerTag__OnStopAtTerra @0x485c00`：
   1. `vf5(2,0,0)` 站立；`vf21` 停止走路音效，并删除炸弹图像；状态 = 8。
   2. 身上有炸弹且计数 < 1：爆炸 `CPlayerTag__OnUseTargetCard`，返回。
   3. 附身警察 / 小偷 / 野狗时执行其动作 `@0x48bd00`，入队 `0x1e`；否则处理与停在同一点的角色的对话 `@0x48ebb0`、`Role_StartNpcDialogForRole`。[M]
   4. 入队 `0x23(点)`（NPC 互动），再入队 `0x1d(点)`（落点事件）。
10. **落点**：
    - **0x23**：`NPC_HandleInteract`。返回 1 时状态 = 10（NPC 演出中）；若该点有 NPC，则在队首插入 `0x65(30)`。
    - **0x1d**：`Role_OnArriveNode @0x4861a0`：
      - 有事件图标且未附身糊涂神：`Role_TriggerLandEvent(事件 id) @0x486140`。电脑走 `AI_OnLandEvent @0x4f79c0`（第 2.5 节）；人类走 `@0x4a4160` 打开事件界面，成功后状态 = 9。
      - 否则先按地块等级调用 `Role_TriggerLandLevelEvent`（事件号 = 等级 + 0x5A）；不成立时入队 `0x12(点)`。
    - **0x12**：`Role_OnArriveCommercialBuilding @0x486260`（商业建筑界面），然后入队 `0x11(点)`。
    - **0x11**：`Role_ProcessArriveLand @0x4868e0`：买地、加盖、付过路费。电脑在这里调用 Python 的 `TBuy`、`TBuild`。
11. **结束**：队列空了之后，状态 8 入队 `0x65(60)` 和 `0x66`：等待 1 秒（受游戏速度影响），然后回到第 1 步。

### 2.4 走路的每一帧 `Role_StepAlongPath @0x485860` [V]

1. 剩余步数 < 1：状态 = 8，返回。
2. 记下 old = from。
3. 调用 `vf17 = Path_AnimateAlongRoute @0x47b730`，移动距离 `dt × 速度(+0x34)`。到达一个道路点时：
   1. 先吸附到该点；
   2. 用 `Path_SelectRandomNext` 选下一个点；from、to 前移一格；
   3. 调用 `vf11 Path_CalcAngle(from, to, 1)` 处理转身；
   4. 剩余步数减 1；
   5. 剩余 < 1：调用 vf19（停下），结束；
   6. 否则调用 `vf18 @0x485a20`（经过道路点）；返回非 0 时，本帧不再继续移动。
4. 若 old 道路点上有事件图标：调用 `Article_PlayDepartEffect(座位, 位置) @0x4ee4f0`。角色离开超过 10 单位时清除该座位的标记位；所有座位都离开后，图标播放动作 1。
5. 调用 `Game_UpdateRoleDirection(old, 位置)`：离开时还原同格的人（第 4 节）。
6. **剩余 == 0**（刚停下）：
   - 对落脚点调用 `Article_PlayApproachEffect(…, 1)`：距离 < 40 且图标上没有别人时，图标播放动作 0，并调用 `CAudioMgr_PlaySample(0x7D = 125, …, 1)`；
   - 调用 `Game_MoveRoleToPosition(from, 位置, 1)`。
7. **剩余 > 0**：
   - 若 from 已经变了（本帧越过了一个点）：对新 from 再做一次离开处理（`PlayDepartEffect` + `Game_UpdateRoleDirection`）。
   - 对 to 调用 `PlayApproachEffect(…, 剩余 == 1)`：不是终点时图标播放动作 2，不出声。
   - 调用 `Game_MoveRoleToPosition(to, 位置, 剩余 == 1)`。
8. 调用 `Camera_SetFocusPoint(位置)`：镜头每帧瞬间跟随。

**经过道路点** `vf18 @0x485a20` 按顺序检查：
1. **炸弹**：计数减 1，到 0 时爆炸并停下（状态 8）；否则可能把炸弹转移给同一格的别人。[M]
2. **NPC**：`vf25` 恒返回 0，所以总会执行 `NpcMgr_CheckPassNode @0x49e090`：依次调用每个 NPC 的虚函数 +0x7C(点)，例如路障、地雷等的拦截。有 NPC 接手时返回 1。
3. **警察 / 小偷 / 野狗**：附身者遇到目标时，站立、停止音效，入队 `0x26`（之后用剩余步数继续走），状态 = 8。
4. **银行**：未附身糊涂神，且格子事件 == 5 时，调用 `Role_TriggerLandEvent(99)`（过路银行）。成功时站立、停止音效；界面或 AI 处理完后，由 `0x26` 接着走。

### 2.5 C++ 与 Python 的交接点 [V]

**结论**：原版的规则引擎（掷骰、走路、买地、付租、事件、NPC、监狱医院等）**都在 exe 的 C++ 里**。Python 脚本只有三类：

1. **电脑决策** `AI_xx.py`
   - C++ 调用入口：`AI_CallScript(n, 参数) @0x4f7810` → `Python_CallFunction @0x5019a0`，按回调名表 0x604558 调用。
   - 回调名与调用位置：
     - 0 Access、8 Borrow：`AI_Event_Bank @0x4f9000`
     - 1 Answer：`@0x4f7fa0`
     - 2 TBuy、3 TBuild：`@0x4fbfe0` / `@0x4fc080`，由 `Role_ProcessArriveLand` 调用
     - 4 SBuy、5 SSell、6 SBuySum、9 SSellAll：`AI_StockTrading @0x4f9310`
     - 7 DiceNum：`@0x4fc120`
     - 10 Count：法院 `@0x4f8810`
   - 落点事件的分派在 `AI_OnLandEvent @0x4f79c0`。
2. **卡片效果** `CardPy_xx.py`：`Execute(param, sa, sb)` 和 `Competence()`。C++ 通过卡片对象的虚函数 `Card_SetCustomValue @0x4ad7a0` / `Card_GetCustomValue @0x4ad410` 调用 → `@0x4ae650` / `@0x4ae580`。触发方式：
   - 人类用卡：消息 2 / 3；
   - 电脑用卡：先在 `AI_PlanCardActions` 中算出计划，再入队消息 3（`Role_FinishCardUse`）。
3. **剧情动画** `daXX_N.py`：Movie 模块，通过 `SpeakAside_InitPython @0x5141b0` 等运行，由消息 0x7e / 0x7f 等进入。[M] 本文未展开。

**Python 回到 C++**：通过 Role / Terra / Street / Npc / Stock / Movie 模块。会改变流程的接口**几乎都是往当前角色的消息队列里塞消息**（已逐个核对 py_* 实现）：

| Python 接口 | 入队消息 | 对应 C++ 处理 |
|---|---|---|
| `Role.Settle` | 0x25(0) | 继续回合 |
| `Role.Wait` | 100 | 重新进入掷骰前判定 |
| `Role.Go(r, n)` | 0x1a(n) | 用指定点数掷骰 |
| `Role.Pause(r, f)` | 0x65(f) | 等待 f 帧 |
| `Role.Prison` / `Role.Hospital` | 0x19 / 0x18 | 进监狱 / 医院 |
| `Role.Become` | 0x24 | 附身 |
| `Role.Hypnosis` | 0x28 | 催眠 |
| `Role.ChgPos` | 0x3d | 换位 |
| `Role.Bubble` | 0x3e | 泡泡 |
| `Role.ReceiveCard` | 4 | 〔string.bin#413〕 |
| `Role.Seal` | 0x59 | 封印 |
| `Role.PlayPrt` | 0x2c | 播放粒子特效 |
| `Role.LostFocus` | 0x2e | 镜头转向他人 |
| `Role.Speak` | 0x5A(台词号) | 说话：`@0x484c30` 即 `Enqueue(0x5A, x, 0)`；分派函数里该处理器被误名为 `CPlayerTag__OnNpcInteract` [H] |

**例外**：`Role.ChgTrfTool(r, t)`（`@0x4fe0c0`）**直接**调用 `Role_SetTrfTool`，不经过队列。

**对移植的含义**：如果移植版想“规则用原版 Python 跑”，C++ 侧至少要实现：
- 消息队列与状态机（本节）；
- 约 130 个 Python 接口；
- 全部消息处理函数（`Role_DispatchQueuedMsg` 的 0x01~0x81 与 0xC9，约 110 个）；
- 事件界面。

Python 本身只负责决策和卡片效果。

## 3. 回合箭头、镜头

### 3.1 回合箭头（截图中当前角色头顶的红橙色箭头）[V]

- **创建**：`Game_StartNewRound @0x4962a0` 和读档 `@0x496a90`，存为 `g_RoleMgr[10]`。
  - 模型 art **6114** = `eff\Eff_08.dff`，带动画 `Eff_08.anm`，`Mesh_SetTexture(0,0,0)` 循环播放动作 0。
  - 缩放 (1, 1.2, 1)。
  - 旋转 yaw = 镜头 yaw − 180，和角色一样朝向镜头。
- **位置**：`当前角色道路点位置 + (0, 10, 0)`。开局在第 1 个角色处；每次换人时在 `Game_TurnNextRole @0x4971a0` 中用 `Mesh_SetTranslation` 移过去。箭头在模型里本身就画得很高。
  - 实机：箭头位置 (−625, 10, 325)，当前角色位置 (−625, 0, 325)，缩放 (1, 1.2, 1)。[V]
- **动画**：每帧在 `@0x495af0` 中更新。
- **显示条件**：在角色渲染 `@0x495bf0` 里，**只有当前角色状态 == 6（等玩家操作）时才画**，画在所有角色之后。电脑回合、掷骰、走路时都不显示。

### 3.2 步数显示
见第 1.7 节（屏幕中上方的 2D 数字，只在状态 1 显示）。

### 3.3 镜头 [V]

**`Camera_SetFocusPoint(p) @0x41d850`** 的计算：
- `Camera_MoveToFocusPoint @0x41b130` 把镜头帧平移到 `p + 距离(−800) × at`；
- 同时把焦点存入 `*(0x61ae00)`。
- 这是**瞬间跳转，没有补间**。
- 实机核对：焦点 (−625, 0, 325)，镜头位置 (−1058.34, 514.23, 758.34) = 焦点 − 800 × (0.5417, −0.6428, −0.5417)。

**一个回合内的调用时机**：
- 回合开始 step 0；
- `Role_LeaveStatus8`；
- `Role_StartRollDice`；
- 消息 0x1e；
- 走路中每帧（`Role_StepAlongPath`）。

所以玩家在等待时把地图拖开，掷骰的那一刻镜头会立刻跳回角色。

**平滑移动**：只在玩家的输入里出现（`@0x4a3960` 平移 / 旋转 / 缩放，`Camera_UpdateSmoothMotion @0x41d000`）。棋盘回合流程里没有找到设置 +0x20 平移标志的代码。[M]
- 平滑移动的参数：加速度 ±5000/s²，速度限制在 500~20000；
- 旋转最多 ±15°；
- 缩放在 −1000~−600 之间。

**镜头忙时**：只要有平移、旋转、缩放在进行，所有角色的状态机都暂停（2.1）。

## 4. 同一道路点上的多个角色

字段（角色）：

| 偏移 | 含义 |
|---|---|
| +0x1F8 | 补间进行中 |
| +0x1FC | 当前比例 |
| +0x200..+0x208 | 当前偏移 |
| +0x20C | 目标比例 |
| +0x210..+0x218 | 目标偏移 |

`g_RoleMgr[4][座位]` 记录每个座位当前“登记”在哪个道路点。[V]

- **“同一点”的判断**：比较两个道路点 +0x00 所指格子的序号。
- **只处理身份状态 ≤ 2 的角色**：正常、冬眠，以及值为 2 的状态。饭店、医院、监狱等状态的人不参与。
- **方向向量**：F = normalize(at.x, 0, at.z)；R = 镜头 right（指向屏幕左侧）。

### 4.1 `Game_MoveRoleToPosition(node, pos, final) @0x4975f0`（靠近一个点）[V]

触发条件：node ≠ 当前角色已登记的点，且 `|node.pos − pos| ≤ 20`。

从当前座位 +1 开始循环遍历其他角色 j（与当前角色在同一点）：

- **final != 0（这一步是终点）**：每个 j（第 k 个，k 从 0 开始）：
  - 目标偏移 = (20 − 20k)·R − 15·F；
  - 目标比例 = **0.5**；
  - 把 j 的登记清为 0。
  - 结果：先在点上的人**缩成一半**，向镜头方向靠前 15，沿屏幕水平方向排开（k = 0 偏左 20，k = 1 居中，k = 2 偏右 20）。
  - 当前角色本身没有偏移，比例保持 1。
- **final == 0（只是路过）**：找到第一个还没有目标偏移的 j，令其目标偏移 = **+15·F**（远离镜头），比例 1.0；已有偏移的人跳过。
  - 结果：站在路上的人往后让 15，走路的人从他前面经过。
- 最后把当前座位登记为 node。

### 4.2 `Game_UpdateRoleDirection(node, pos) @0x497a10`（离开一个点）[V]

触发条件：node == 当前角色已登记的点，且 `|node.pos − pos| > 15`。

遍历同一点上的其他角色 j：
- 目标比例 ≠ 1（被缩小的人）：记下第一个，继续找。
- 目标比例 == 1 且有目标偏移（路过时让开的人）：把他还原为偏移 0、比例 1（`Role_CheckPathValid @0x4816f0`），然后结束。
- 若没有找到需要还原的“让开者”，但有被缩小的人：只还原记下的第一个（偏移 0、比例 1），并把他登记到该点。

最后把当前座位的登记清为 0。

### 4.3 补间 `CPlayerTag__vf28_Update @0x4818d0` [V]

每帧计算：
- d = 目标偏移 − 当前偏移；L = |d|；step = dt × 100（**每秒 100 单位**，匀速）；
- 比例 = 当前比例 + (100/L)·(目标比例 − 当前比例)·dt，也就是比例和位移在同一时刻到达终点；
- **step < L**：位移 += d̂·step，并更新比例；
- **否则**：当前偏移 = 目标，比例 = 目标，结束补间。

注意最后一帧：模型实际平移的是 **d̂·step**，而不是 d̂·L，所以会**多走 (step − L)**（反汇编确认，盲审也独立指出）。这个误差会留在模型位置里，直到下一次 `Mesh_SetTranslation` 的绝对定位，例如走到下一个道路点时被吸附。

**其他要点**：
- 模型缩放 = 状态外形（`CPlayerTag__GetStatusShape`）× 当前比例。
- 补间进行中这个角色的状态机暂停（2.1）。
- 其他相关函数：
  - `Role_SetMovePath(偏移, 比例) @0x4816a0`：设定目标并开始补间；
  - `Role_HasMovePath @0x481840`：判断目标偏移是否非 0；
  - `Role_CheckPathSpeed @0x4818a0`：判断目标比例是否 ≠ 1；
  - `Role_ResetMovePath @0x481760`：立即撤销偏移，把模型移回中心并恢复缩放。

## 6. 移植实现清单（按顺序）

1. **消息队列 + 状态机骨架**：
   - `{cmd, a, b}` 队列，支持 `EnqueueMsg` / `EnqueueMsgAt(0)`；
   - 状态 0/1/3/4/5/6/8/9/10；状态 8 每帧只处理一条消息；
   - 队列为空时入队 0x65(60) + 0x66；
   - 等待时间乘以 (1 − (speed − 1)/10)；
   - 镜头忙、补间、转身时暂停状态机。
2. **换人**：`TurnNextRole`（跳过破产者）→ 0x68 → 0x67(0..6, 9) → 0x25 → `BeforeRollDice`。先用占位的“人类 / 电脑”判断：电脑直接掷骰，人类进入状态 6 并等待掷骰按钮。
3. **骰子**：12 张贴图；Im3D 公告板（50×50，手持阶段缩放 0.8）；按 0.3 s 手持 → 17 × 0.04 s 滚动（高度表 + 绝对高度）→ 1.0 s 停留的时间线；第 12 帧播放音效 9；两处绘制位置与条件（1.6）；结果交给 `BeginMoveSteps`；dicePos 的 x 按朝向翻转。
4. **走路**：`BeginMoveSteps`（动作 0、走路循环音效）→ 每帧推进 → 经过道路点的回调（先留空，或只做银行）→ 停下（站立动作、停音效、状态 8、入队 0x23 / 0x1d）。走路时画屏幕上方的 2D 步数数字（number.tga，POINT 采样）。
5. **镜头**：在回合开始 / 掷骰 / 每帧走路时瞬间对焦（焦点 − 800·at），与原版完全一致。
6. **回合箭头**：Eff_08（art 6114），位置为道路点 + (0, 10, 0)，缩放 (1, 1.2, 1)，只在状态 6 显示。
7. **同格错开**：4.1 / 4.2 / 4.3。包括阈值 20 / 15、偏移 ±20、±15、比例 0.5、速度 100/s；如要逐像素一致，最后一帧的多走误差也要复刻。
