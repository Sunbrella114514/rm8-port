## 2. 玩法与操作（代码依据）

这是**不对称的 1~2 人游戏**：底部的“小厨师”接食物，顶部的“扰乱者”往下扔杯盘/蟑螂。模式字段 `+0x1ac` 在 `Game_Init@1002cc20` 里由主程序传入的玩家表决定：

| `+0x1ac` | 含义 | 判定（`Init`） |
|---|---|---|
| 0 | 当前玩家（小厨师）是人类，其余玩家全是 AI → 扰乱者由 AI 控制 | `params[0x12]!=1` 且其他玩家都不是类型 2 |
| 2 | 当前玩家是人类，且至少有另一名人类 → 双人同键盘 | 其他条目 `params[i*0x15+0x12]==2` |
| 1 | 当前玩家（小厨师）是 AI，人类控制扰乱者 | `params[0x12]==1`；按主程序代码，18~23 号事件里 AI 玩家走随机结算（见 §6.5），实际**不会出现**该模式（推论） |

玩家类型值来自主程序 `FUN_0050ddd0`：玩家 `+0x1b0==0`（人类）记 2，否则记 1。

**键位**（`OnKeyDown@10034c40`、`OnKeyUp@10035160`；键码是主程序输入层的内部码，`FUN_00407d20` 也使用同一套 0x61/0x64/0x73/0x77/0x93~0x96）：

| 角色 | 键 | 作用 |
|---|---|---|
| 小厨师（模式 0/2） | `a`(0x61) / `d`(0x64) | 向左 / 向右走（速度见 §3） |
| | 空格(0x20) | 跳；与方向键组合得到“带方向的跳”（状态 3/4） |
| 扰乱者（模式 1/2） | 0x95 / 0x96 | 向左 / 向右（与 `a`/`d` 配对，推测为方向键 ←/→，和说明文字一致） |
| | 0xab | 扔出手里的物品（推测为 Enter，与说明文字一致） |
| 任何人 | 空格 / 0xab | 同时关闭“说明”面板（`CloseIntro@10035030`）开始游戏；说明面板上的“确定”按钮(控件 id 2，`Init` 为其注册回调 `FUN_10035730`，事件值为 2 时调用 `CloseIntro`)点击也能开始 |

没有 ESC 处理；`w/s`、0x93/0x94 分支是空的。鼠标不参与操作（`OnMouseButton@10035570`、`OnMouseMove@10035670` 基本是空壳）。

**玩法细节**

- 食物从屏幕顶部 8 个等分列中随机生成（`Update@1002fb50`，调试名 `droppingItem`）：每帧尝试 3~7 次(`rand%5+3`)，随机挑一列，若该列冷却 `<0` 就生成一个食物，并把该列冷却设为 {1,3,5} 秒之一(表 `0x10088d74`)。食物类型按 `rand()/32767` 分段：[0,0.1)→类型0，[0.1,0.3)→1，[0.3,0.5)→2，[0.5,0.7)→3，[0.7,0.9)→4，[0.9,1)→5。初速 = {2,4,6}[rand%3] × 地面高度/7(表 `0x10088d68`)，之后受重力 `+0x1f4`(=纵向缩放×100) 加速。
- 扰乱者（顶部、位置 `+0x38`）每次扔出的物品类型：`rand%100` <37 → 类型1（-40），<70 → 类型0（-30），其余(70~100，约 31%) → 类型2（蟑螂）。扔出物初速 = 地面高度(px/s)，类型 0/1 受重力，类型 2 匀速。
- 模式 0 的 AI 扰乱者：每帧 40%(`rand%10<4`) 概率向小厨师 x 靠近（速度 = 小厨师基础速度×2.1，距离需 >屏宽/27），每 1.5 秒(`+0x220`重置为 0x3fc00000)扔一次；模式 1 的 AI 小厨师用 `ChefAI_PickTargetX@1002c440` 在 8 个分段里找权重最大的列并移动。
- 蟑螂（类型2）落地后变成沿地面左右爬行的“黑蟑螂”(`crawlBlackBeatle`，向量元素 0x18 字节，速度=屏宽/4×方向)；小厨师碰到飞行中或爬行中的蟑螂都会触发游戏结束（`DrawAndCollide@10033100` 中 `+0x1d8=1`、音效 0x15d、硬直 2 秒）。
- 杯/盘落地或被接住会生成 0.3 秒的碎片特效(`flashItem`，元素 0x14 字节)。

## 5. 与主程序的接口

### 5.1 加载与导出

`CMiniGameHost`（vtable `005e88e0`，17 项）的 `vf16 = FUN_0050ddd0` 完成：`LoadLibraryA(gamelib\ltlgame_%02d.dll)` → `GetProcAddress("LG_create_game"/"LG_delete_game")`（保存在对象 `+0x14/+0x18`）→ 创建一个宿主接口对象（4 字节，vtable `0x005e8928`，共 81 项）→ 整理玩家参数块 → `game = LG_create_game()`(`+8`) → 调用 `game->vtable[0](hostInterface, &params)`，返回非 0 则隐藏主界面并开始。`LG_create_game@1002a3dd` = `operator_new(0x294)` + 构造 `FUN_10036050`；`LG_delete_game@1002a28e` = `FUN_100362a0(1)`（虚析构+free）。

### 5.2 游戏对象虚表（`0x1007f100`，10 项；主程序只会调用前 8 项）

| 偏移 | 函数 | 作用 | 主程序调用者 |
|---|---|---|---|
| +0x00 | `Game_Init@1002cc20` | 初始化(host, params)，返回 bool | `FUN_0050ddd0` |
| +0x04 | `Game_GetResult@1002fa60` | 把结果写入主程序缓冲并释放资源 | `FUN_0050e300`（清理） |
| +0x08 | `Game_Update@1002fb50` | 每帧更新(dt 秒)，返回 false = 游戏结束 | `vf1 FUN_0050ecd0`（false 时主程序得 0x80000000） |
| +0x0c | `Game_DrawAndCollide@10033100` | 绘制+碰撞+计分（注意：计分在“绘制”里） | `vf2 FUN_0050ed10`（参数为 0 时） |
| +0x10 | `Game_OnKeyDown@10034c40` | 键按下 | `vf5 FUN_0050ed50` |
| +0x14 | `Game_OnKeyUp@10035160` | 键抬起 | `vf6 FUN_0050ed80` |
| +0x18 | `Game_OnMouseButton@10035570` | 鼠标键位图（`vf9 FUN_0050ee30` 把输入标志位重映射为 0x10/0x20/0x40/0x100/0x200/0x400 后传入） | `vf9` |
| +0x1c | `Game_OnMouseMove@10035670` | 鼠标 (x,y)/滚轮，18 号几乎不用 | `vf7/vf8` |

### 5.3 宿主接口（`this+4`，主程序 vtable `0x005e8928`）中 18 号用到的项

`+0x50` 按资源 ID 创建精灵/模型(返回句柄)、`+0x54` 释放、`+0x64` 设缩放、`+0x68` 设位置、`+0x78` 推进动画(dt)、`+0x7c` 绘制、`+0x8c` 取包围盒(第 3 个 float 为宽)、`+0xc8` 向量归一化、`+0xf0` 画 2D 贴图四边形(头像框)、`+0xfc` 读 `string.bin` 字符串、`+0x100/+0x104/+0x110` 空实现(+0x100 返回 -1)、`+0x108` 播放 BGM、`+0x114` 在位置播放音效(id,pos,音量,…)、`+0x120/+0x124` 窗口宽/高、`+0x128` 鼠标位置、`+0x130` 显示/隐藏光标(Init 时和结束时都传 1)、`+0x13c` 返回主程序 UI 管理器指针(DLL 把它存到 `DAT_1067e7e8`，用 DLL 自带的一份 UI 库代码操作它)、`+0x140` 返回游戏目录路径、`+0x20/+0x40/+0x44/+0x48` 空实现。

### 5.4 参数块（`Init` 的第二个参数）

主程序栈上构造：`[0]`=玩家数；其后每名玩家 0x54 字节(21 个 dword，当前玩家排第 0 位)：`+0` 玩家槽位、`+4~0x43` 名字、`+0x44` 类型(1=AI、2=人类)、`+0x48/+0x4c/+0x50` 角色头像纹理指针等。**18 号只读取**：`params[0x12]`（第 0 位的类型）、`params[i*0x15+0x12]`（其他玩家类型）、`params[0x28]`（第 1 位玩家的头像纹理指针，存 `+0x58`，在顶部扰乱者位置画 100×100 头像框）。参数块末尾的难度×2(`[0xa9]`)和 `[0xaa]` 未被使用。

### 5.5 结果结构与奖励（`FUN_0050e300`）

`GetResult` 写 `param_1[0]=1`（人数）、`param_1[2]`=得分(`+0x1bc`)、`param_1[4]`=评级(`+0x290`)；`param_1[1]`（玩家槽位）和 `[3]` 不写。主程序随后：

1. 弹文案 `string[0x14c2]`(=5314，“%s玩快手小廚師小遊戲，獲得%d點券”)；
2. **点券 = 得分**：`FUN_00484890(7, 得分, 1)` → 消息队列 case 7 → `Role_AddTicket`（`+0x324`，上限 9999；第三参数 1 表示不触发随机反应台词）；
3. **卡片奖励**：得分 ≥180 发卡片索引 0x12；100~179 发 0x14（`FUN_00484890(4, idx, 0)` → 消息队列 case 4 → `FUN_00488e80(idx,0)` 给当前玩家加卡，按卡表向量下标取卡；`FUN_004adec0` 按 card.bin 顺序 `push_back`，故下标=Id-1 → 0x12=Id19 核子飛彈，0x14=Id21 均富卡，推测）；<100 无；
4. 评级 0/1/其它 → 台词类别 4/1/2（`FUN_00484c30`→消息 0x5a，具体表现未核实）；
5. `FUN_004aa5d0(事件号-0x11, 得分)` 更新该小游戏的个人最高分（统计对象 `+0x840+4*idx`，上限 9999）。

奖励只发给**当前玩家**（小厨师）；第二名人类（扰乱者）在 18 号事件里没有奖励。

### 5.6 AI 玩家

AI 不会实际运行 DLL：`AI_OnLandEvent@004f79c0` 对事件 0x12~0x17 调 `FUN_004fcb10`，直接按 init.txt 的 `difficuty`（`FUN_00401060(7)`，本机=3）随机生成分数并发点券：18 号 `difficuty<3` 时得分 = `rand%60+20`(20~79)，否则 `rand%100+40`(40~139)；消息同样用 5314，点券 `FUN_00484890(7, 得分, 0)`（第三参数 0 允许随机反应台词）。AI 路径不发卡片。

## 8. 推翻的上一版结论

1. “`LG18_calc_score@10031b50` 计算得分”——它是 HUD 绘制(倒计时数字、得分数字、Ready/Go/结束横幅)并在结束后按得分写评级；得分在 `DrawAndCollide@10033100`（虚表+0x0c）里累加。
2. “`LG18_show_game_result@1002fa60` 显示结果画面”——它是虚表+4 的 **GetResult**：填结果结构、释放资源、显示光标，不画任何画面。
3. “`LG18_vtable_init@10036050` 初始化虚表”——它是对象构造函数；`LG18_game_init@1002cc20` 才是虚表[0]（Init）。
4. “`+0x1ac` 是难度(0/1/2)，难度会改变出怪速度，有难度选择界面”——它是**操作者模式**（谁是人类），游戏没有难度分级，也没有难度选择界面；lg_intro.ui 只有一个说明面板+确定按钮。
5. “得分来自收集数、剩余时间奖励、难度倍率、连击”——全部不存在；实际是固定分值（食物 8/6/3/5/3/5，杯盘 -30/-40），蟑螂直接结束。
6. “快手小厨师=接掉落物品”——只对一半：还有对手扔杯/盘/蟑螂、双人对抗、蟑螂终结游戏、40 秒限时。
7. “`+0x120/+0x148/+0x170` 各 10 个 = 三组物品槽 / `+0x198` 特殊物品 / `+0x1c4~+0x1c8` 计时值 / `+0x1b1~+0x1b2` 阶段标志”——前者是三组数字精灵(得分/倒计时)，`+0x198/+0x19c` 是 "-"/"+" 符号精灵，`+0x1a0/+0x1a4` 是倒计时底图；真正的计时是 `+0x1c0`。
8. “`LG18_load_music` 载入 L001.mp3 并在游戏中播放”——接口 `+0x100` 在主程序是恒返回 -1 的空函数，该文件不会播放；背景乐由 `+0x108(0x15,0)` 触发。
9. “`LG18_setup_colors` 设置界面/渲染颜色”——设置的是光照颜色与方向，且 `+0x40/+0x44/+0x48` 在主程序侧是空函数。
10. “vtable 偏移 +0x108 计时/帧设置，+0x130 游戏初始化标志，+0x13c/+0x140 资源路径获取，+0x200 颜色集，+0x40/+0x44/+0x48 UI 回调注册；`+4` 指向 vtable”——实际见 §5.3：+0x108 播放 BGM、+0x130 显示光标、+0x13c 返回主程序 UI 管理器、+0x140 游戏目录、+0x200 不存在、+0x40~+0x48 空实现；`+0` 才是 vtable，`+4` 是宿主接口指针。
11. “游戏名 Dou Shou Qi 8 (大富翁8)”——写错了游戏名；本游戏是《大富翁8》的小游戏。
12. 命名统计“H 级仅 11 个、209 个 L”——已改为按 STL/UI 库/游戏逻辑逐类重命名（见 `out/names_llm/lg_18.tsv`）。
