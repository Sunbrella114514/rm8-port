## 1. 游戏是什么（官方文字 + 代码）

官方文字（`Config/string.bin`，`out/config_utf8/string.bin.txt`）：

- 说明（6953，`LG20_Game_Init` 里 `host+0xFC(0x1b29)` 取，显示在 `lg_intro.ui` 引导界面）："一、玩家控制滑鼠打地鼠。二、〔string.bin#6953〕。三、〔string.bin#6951〕40秒。"
- 简介（6974）："〔string.bin#6974〕，〔string.bin#6974〕，〔string.bin#6974〕，〔string.bin#6974〕，2P〔string.bin#6974〕。"
- 结果提示（5316）："%s〔string.bin#5316〕，获得了%d点券"。

代码与之一致 [已验证]：3x3 共 9 个洞；1P 用**鼠标左键**点击出洞的"神仙"(地鼠)；每次命中按类型加/减分；另有"扰乱者"(类型6)，由键盘数字键 1-9 / 小键盘在对应洞里放出，打中它扣 10 分；比赛 40 秒。**上一版"用数字键 1-9 打地鼠"完全相反**：数字键是扰乱者放出的入口，不是打地鼠。

## 2. 流程（状态机，`LG20_Game_Update` 10001c40，`this+0x2cc`）[已验证]

| 状态 | 含义 | 计时 | 转移 |
|---|---|---|---|
| 0 | 引导界面(lg_intro.ui)，等待开始 | 无 | 回车(0xAB)/空格(0x20) 或点按钮(控件ID 2，回调 10002530) -> `LG20_StartGame`(100017b0)：播 0x131，`host+0x130(0)` 隐藏系统光标，状态1，播 0x12d |
| 1 | 准备 | `this+0x3a0`=2.0 秒 | 到 0 -> 状态2；Draw 在该状态显示准备/开始牌(0x84b/0x84c)，整数秒变化时按缓存 `this+0x3a8` 去重并播 0x165(边界未细查) |
| 2 | 比赛 | `this+0x39c`=40.0 秒 | 期间每帧调 `LG20_Field_Update`；到 0 播 0x130，进状态3 |
| 3 | 结算牌 | `this+0x3a4`=1.0 秒 | 计时到 -> 状态4(`this+0x3a4`重置 1.0)；本状态里按分数档播结果音效一次 |
| 4 | 评价牌 | 1.0 秒 | 到 0：`this+0x2b8=0`，`Update` 返回 false，宿主结束游戏 |

`FUN_10005e10` 是空函数(Update 里调用但没作用)。

## 3. 操作 [已验证]

- **1P 鼠标**：`vtable[6]`=`LG20_Game_OnMouseButton`(10001de0，Ghidra 未识别，仅汇编)。标志 `0x40`(宿主把外部"0x100|0x10"映射成 0x40，推测为左键按下)：状态非0 时播音效 0x142；光标精灵换成 `this+0x398`(0x6bb)；状态2 时调 `LG20_Field_OnClick(x,y)` 做命中判定。标志 `0x400`(推测为左键释放)：光标精灵换回 `this+0x394`(0x6ba)。状态0/1 中的点击只有音效。游戏开始后隐藏系统光标，改画锤子光标精灵 `this+0x2d8`。
- **2P 键盘(扰乱者)**：`vtable[4]`=`LG20_Game_OnKey`(10001da0，汇编)：状态2 时转给 `LG20_Field_OnNumpad`(10002cf0)；状态0 时 0xAB/0x20 开始游戏。
  - 键码 `'1'..'9'`(0x31-0x39) 与小键盘码 0x99-0xA1 映射到洞位：7/8/9->洞 0/1/2(上排)，4/5/6->洞 3/4/5(中排)，1/2/3->洞 6/7/8(下排)(即数字小键盘的位置)。
  - 若场上没有扰乱者(没有 slot 的 id 等于 `field+0x108` 或 `field+0x104`)，则把目标洞的 slot 改成扰乱者：id=`field+0x108`(精灵 0x6be)、类型=6、可击中标志=1、生命=2.0 秒、出洞延时清0(**会覆盖该洞原有的地鼠**)。同一时刻最多一个扰乱者；没有冷却时间限制，除了"场上有扰乱者时不能再放"。
  - DLL 不判断"是否真有第二个人"：键盘事件谁按都算，单人也可以自己左手键盘右手鼠标。
- 命中判定 `LG20_Field_OnClick`(10005840)：以光标为基准取 3 个探测点 (x-22s,y+21s)、(x-11s,y+20s)、(x+3s,y+17s)(s=缩放，锤头位置)，必须都落在场区矩形(原点(185,118)xs，宽432 高348，`field+0x330`)内；然后逐洞用 `host+0xb4`(点是否在精灵内)测地鼠精灵，且 slot 可击中标志(`+0x1d0`)为 1、id≠-1、点击点在该洞地鼠当前顶端以下(`field+0x358+i*4`)。命中后：
  - slot id 换成"被击中"精灵 `field+0xec+类型x4`(0x6bf..0x6c5)，可击中标志=0，保持计时 `+0x304`=0.3 秒；
  - 若已出洞时间(`+0x2bc`)>0.2 秒，则生命(`+0x298`)=已出洞时间，已出洞时间=1.2；否则生命>0.2 时截为 0.2——即被打中后很快缩回；
  - 播命中音效：类型0-5 在 0x143-0x147 随机(rand%5)，扰乱者在 0x148-0x14a 随机(rand%3)(音效 id 表在 `field+0x37c`)；
  - 设锤击特效精灵 `field+0x134`(0x6b2) 的位置；压入得分浮字(`+0x1ac` 向量，每项 0x14 字节，显示 2.0 秒)；
  - `field+0x32c += 得分表[类型]`，**夹到 0..999**，同步 `game+0x2d0`。

## 4. 计时 [已验证]

- 比赛 40.0 秒：`game+0x39c`(HUD、状态机用) 与 `field+0x294`(出怪阶段用) 两个独立计时，初值都是 40.0，状态2 里同步递减。
- 右上角显示 `ftol(剩余秒数)`，<=6 秒用红色数字集；最后 5 秒(整数秒<5)在屏幕上方中央显示大数字倒数并每秒播 0x12f。
- 准备 2.0 秒，结算 1.0+1.0 秒。

## 5. 计分 [已验证]

### 5.1 得分表(`LG20_Field_InitTables`，10003380，`field+0x190..0x1a8`)

| 类型(slot+0x1cc) | 来源 | 命中得分 |
|---|---|---|
| 0 | 随机出怪 | **-2** |
| 1 | 随机出怪 | **+2** |
| 2 | 随机出怪 | **+3** |
| 3 | 随机出怪 | **-3** |
| 4 | 随机出怪 | **-5** |
| 5 | 随机出怪 | **+5** |
| 6 | 2P 扰乱者 | **-10** |

官方文字说"〔string.bin#6974〕，〔string.bin#6974〕"：加分的 3 类(1,2,5)是"坏神仙"、减分的 3 类(0,3,4)是"好神仙"；游戏里共有 6 位神明(财神/穷神/衰神/福神/〔string.bin#549〕/糊涂神)，对应关系为 [推测]。资源包里有 6 套地鼠贴图 `prt\ui\mini game\03\g03n01..g03n06_1..5`(各 5 帧)和第 7 套 `g03n07/g03n07_1`(扰乱者)，数量与类型 0..6 吻合 [推测]。
各类型出怪概率均为 1/6(`rand%6`)，所以随机出怪的数学期望为 0，要靠准确打"坏神仙"并避免"好神仙"才能得分。

### 5.2 总分

- 总分 = Σ 命中得分，实时存在 `field+0x32c`，**每次命中后夹到 [0,999]**(中途变负会被夹回 0，之后再加)，并写入 `game+0x2d0`。没有时间奖励、没有连击倍率。上一版所谓"得分倍数(0x304…)"其实是"被打中后保持 0.3 秒"的计时。
- 评价档(`LG20_Game_Draw`，状态3)：分数 <=40 -> 档0(音效 0x135)；41..100 -> 档1(音效 0x134)；>=101 -> 档2(音效 0x15c)；写入 `game+0x2d4`，随结果结构返回。结算牌/评价牌也按同阈值选图(状态4)。
- 未命中、点空白不扣分。

## 6. 难度(出怪，`LG20_Field_SpawnAndExpire` 10003720 / `LG20_Field_Update` 10004d20) [已验证]

阶段由 `field+0x294`(剩余时间，取整)决定：

| 阶段 | 剩余时间 | 同屏地鼠数(每帧补足) | 生命 |
|---|---|---|---|
| 0 | >27 秒(前 13 秒) | `rand%3+1` = 1-3 只 | (`rand%11+8`)x0.1 = 0.8-1.8 秒 |
| 1 | 13<..<=27 秒 | `rand%4+2` = 2-5 只 | (`rand%10+6`)x0.1 = 0.6-1.5 秒 |
| 2 | <=13 秒(最后 13 秒) | `rand%5+3` = 3-7 只 | (`rand%6+5`)x0.1 = 0.5-1.0 秒 |

(生命公式 `(rand % (A-B) + A) x 0.1`，常量表 `DAT_10041040` = (A,B)=(8,19)/(6,16)/(5,11)；`A-B` 为负，MSVC 取余结果非负、范围 [0,|A-B|-1]。)

- 每只新地鼠：类型 `rand%6`，随机选一个没有占用的洞(`slot.id==-1`)，精灵取 `field[5+类型x9+洞]`；出洞延时 `rand%230 x 0.01` = 0-2.29 秒(之后才开始计"生命")；若场上已无人出洞则让最后一只延时清0，若完全没有地鼠则新生成的第一只延时为 0。
- slot 每帧：出洞延时(`+0x2e0`) -> 击中保持(`+0x304`) -> 生命(`+0x298`)递减、已出洞时间(`+0x2bc`)累计(`LG20_Field_Update`)；生命<=0 清空 slot。
- 地鼠出洞/缩回有 0.2 秒的位置插值(`LG20_Field_DrawMoles`)。
- 难度只和剩余时间有关；宿主参数块里的 `init.txt difficuty`(x2) 本 DLL 未读取。

### 8.6 结果结构(`Finish(out)` 写出，10002860) [已验证]

```
out[0] = 玩家数 count(this+8)
对每个玩家 i (每项 5 个 int，从 out[1] 起)：
  out[1+5i] = 座位号 players[i].seat
  out[2+5i] = 分数：i==0 时 = game+0x2d0；i>0 时 = 0
  out[3+5i] = 0
  out[4+5i] = 评价档 game+0x2d4 (0/1/2)
  out[5+5i] = out[2+5i]
```
宿主在 `FUN_0050e300` 里只读第一项：`score=out[2]`，评价档 `out[4]`。

### 8.7 主程序如何据分数发奖(`FUN_0050e300`) [已验证]

事件 20，`score>0` 时：

1. 弹出文字 5316 "…〔string.bin#5316〕，获得了%d点券"；
2. `FUN_00484890(7,score,1)`：**角色点券(role+0x324) += score，上限 9999**；
3. 卡片(脚本命令 4 -> `FUN_00488e80(idx)`，idx 为 card.bin 下标，Id=idx+1)：`score>=150`(0x96) -> idx 0x12(Id19 核子飞弹)；否则 `score>=100`(0x64) -> idx 0x11(Id18 飞弹卡)。分数<100 没有卡片；
4. 评价表情：`out[4]` 0->`FUN_00484c30(4)`、1->(1)、其余->(2)(脚本命令 0x5a，推测为角色表情)；
5. 最高分记录：`FUN_004aa5d0(event-0x11=3, score)`(`0x61ae08+0x840+3*4`，取较大值，上限 9999)。

因 `game` 内分数夹在 0..999，故 >=100 才有飞弹卡、>=150 才是核弹，实际可行(正常高分约 100-300)。

AI 玩家(`FUN_004fcb10`)：读 init.txt `difficuty`(`FUN_00401060(7)`)，<3：`rand%50+10`(10..59)；>=3：`rand%80+30`(30..109)；弹文字 5316 并 `FUN_00484890(7,score,0)` 给点券，**无卡片奖励、不记最高分**。

## 11. 推翻的上一版(lg_20.md / lg_20.tsv)结论

1. **"控制方式：键盘数字键 1-9 对应 9 个地鼠位置，按键击打"**——推翻。1P 用鼠标点击击打；数字键/小键盘是 2P "扰乱者"放出类型6 扰乱者(-10 分)的入口(`FUN_10002cf0`)。上一版"4/5/6、7/8/9、+"完全是误读 switch。
2. **"状态机 4 个状态，状态2结束触发 FUN_10004d20 最终计分"**——更正：状态是 0-4(0 为引导界面)；`FUN_10004d20` 不是最终计分，而是比赛期间每帧的地鼠场更新(出洞/生命/动画/出怪)；40 秒到期只是切到状态3 播音效。
3. **"最大累积得分存储在 offset 0x700"**——推翻：游戏对象只有 0x3c4 字节，偏移 0x700 不可能存在；真实分数在 `field+0x32c`(0..999)，同步到 `game+0x2d0`。
4. **"得分倍数机制允许连续击打同一地鼠时扣减倍数(0x304…)"**——推翻：`+0x304..` 是各洞被击中后的"保持 0.3 秒"计时，没有倍率机制。
5. **"若倍数<=0 直接从 0x298 更新累积得分"**——推翻：`0x298..` 是各洞地鼠"生命"秒数，不是得分。
6. **"9 个地鼠独立计时体现并行打地鼠；清理 30 个 UI 元素(3 行 10 列)"**——更正：9 个 slot 各有出洞延时/生命/击中保持；清理的是 3 组各 10 个数字精灵与若干牌子精灵。
7. **"LG20_Init_Mole_Positions 初始化 9 个地鼠位置参数：6 行 9 列随机数组"**——更正：`FUN_10002e70` 是创建精灵(6 类地鼠 x 9 洞的精灵 ID 表 + 其他精灵)，不做随机；洞位置在 `FUN_10003380`。
8. **"日志文件 MouseScoreLog.txt 记录每轮得分"**——推翻：字符串没有任何引用。
9. **"虚函数 0x20 清理前置资源、0x110 加载资源(FUN_10001100)、0x114 配置UI元素、0x128 参数查询、0x130 播放音效"**——更正：宿主接口 0x20 是空实现，0x110 也是空实现，0x114=播放音效(id,句柄,音量,标志)，0x128=取光标位置，0x130=显示/隐藏系统光标；`FUN_10001100` 是 `LG20_PlayBGM`(调 0x108)，不是加载 UI。
10. **"offset 0x2c8/0x2cc/0x2d0 等对象成员表"**——大部分更正，见 §9(例如 0x2cc 状态有效、0x2d0 是分数、0x2d4 是评价档、0x2d8 是光标精灵，而 0x2f0 起是数字精灵集)。
11. **"LG20_Display_Final_Score 显示最终得分：释放得分显示对象"**——更正：`FUN_10002cd0` 只绘制锤击特效精灵 0x6b2。
12. **"LG20_Frame_Update 主更新循环：清理/渲染地鼠/计分"**——更正：`FUN_10001ea0` 是 `vtable[3] Draw`(Update 是 10001c40)。
13. **"LG20_Load_HitMouse_UI / Game_Init_Parameters / Start_Game_Intro(设置状态 0x12d)"**——更正：10001100=播 BGM；10001140=创建 HUD/结果精灵；100017b0=开始游戏(0x12d 是音效 id，不是状态)。
14. **"返回值：向主程序返回最终得分，主程序给予奖励"**——只对一半：现已补出结果结构(§8.6)与奖励规则(§8.7)：点券 += 分数，>=100 飞弹卡、>=150 核子飞弹，AI 的随机分数区间等。
