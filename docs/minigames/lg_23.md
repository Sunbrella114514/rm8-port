## 2. 玩法与操作

**核心规则**：画面左右各有一根“管子”往中间射蛋，蛋沿水平方向横穿画面。玩家控制的“踩蛋人（小丑）”固定在画面底部中央，只能**原地跳跃**（不能左右移动），在下落时踩中蛋得分。

- **操作**（`OnMouseButton@10044300`、`Clown_Update@1003ec70`）：按住鼠标左键起跳（输入标志位 `&0x40` 视为按下、`&0x400` 视为抬起，推测对应左键）；按住期间每帧把竖直速度重置为向上 `1000×缩放`，最长 0.25 秒（`+0x74` 累计达 0.25 后强制松开）；中途松开则提前结束上升，所以是可变高度跳。受伤期间(`+0x7c>0`)不能起跳。跳跃时播放音效 0x159。
- **a/d/w/s 与方向键**在 `OnKeyDown@10043e90`、`OnKeyUp@10044210` 里分支全部为空，踩蛋人**不能**用键盘移动。
- **踩踏判定**（`PipeEggMgr_CollideEggs@10039270`）：飞行中的蛋与踩蛋人矩形相交，且踩蛋人**正在下落**(`vy≥0`)、**未受伤**(`+0x7c≤0`) 时算“踩中”：踩蛋人获得向上弹力(`vy -= 1000×缩放`)，蛋改为向下掉落(`vy=1000×缩放`)转入“下落蛋表”，音效 0x157，并加分（见 §3）。相交但不满足踩踏条件时调用 `Clown_OnHit@1003ea60`：音效 0x158，受伤 2.0 秒（不能跳、不能踩），受伤精灵 0x7e1，`+0x80` 减 1（该字段没有其他读者，实际无效果）。**被撞不扣分。**
- **管子与蛋**（`PipeEggMgr_UpdatePipes@1003a420`、`FireLeftPipe@10039fe0`、`FireRightPipe@1003a200`）：左管（高处，x=48×缩放，管口 y≈H-492×缩放）发射“蛋精灵 0x7d4”，水平向右 450×缩放 像素/秒；右管（低处，x=W-48×缩放，y≈H-300×缩放）发射“0x7d5”，水平向左 350×缩放 像素/秒。管子计时 `+0xe8`(左，初值 4.0)、`+0xec`(右，初值 2.0)，剩余 <0.5 秒时变色预警，到 0 播放发射动画，动画结束才真正生成蛋，之后计时重置为 4.0 秒。故右管约在开场倒计时结束后 2 秒首发，左管约 4 秒首发，之后每管约每 4 秒一个（均加上动画时间，推导）。蛋飞出屏幕 ±32×缩放 外即删除（`PipeEggMgr_Update@100389f0`）。
- **擾亂者（模式 2，第二名人类）**：用 0x93/0x94（与 w/s 配对，推测为 ↑/↓ 方向键）“摇晃管子”。`OnKeyDown` 先把按键交给 `ShakeMeter_CountArrowKey@10044060`（0x94 计数+1，0x93 计数-1），`ShakeMeter_Tick@10043ca0` 每 ≥250 毫秒把 速率=计数/0.25 并清零；`PipeEggMgr_Update` 中 `DAT_100af640`（管子晃动相位）每帧 `+= dt×50×速率`（超 360 回 0），管口高度偏移 `+0x11c = sin(相位)×3 + 10×速率/2`（缩放前），因此按键越快，管口越高低起伏。**仅模式 2 有这个偏移**（`game+0x24==2`），其余模式管子静止，没有 AI 扰乱者。
- **模式** `game+0x24`（`Init` 与快手小厨师相同的玩家表判定）：0 = 当前玩家人类、其余全是 AI；2 = 另有人类扰乱者；1 = 当前玩家是 AI（主程序对 23 号事件的 AI 玩家走随机结算，实际不会运行 DLL，推论）。
- **开始与结束**：开场说明面板由空格(0x20)/0xab(推测 Enter)或面板“确定”按钮（控件 id 2，回调 `FUN_10044740`→`CloseIntro@100440e0`）关闭，`+0x50` 清零后开始；60 秒到、或 0x80（推测 ESC，`OnKeyDown` 把 `+0x30` 置 0）结束。另有一个“管子可用”标志 `PipeEggMgr+0xf0/+0xf1`：落地蛋堆最后一个蛋的高度升到管口高度以上时被清零，`GetFlagF1@10043c60`==0 时 `Update` 会把踩蛋人切到精灵 0x7e3 并置结束标志 `+0x20`——这条“蛋堆过高提前结束”的触发场景**未能确认**（推测）。

### 5.4 参数块、结果结构与奖励

参数块同 18 号（`[0]`=玩家数，每人 0x54 字节，类型在 `+0x44`：1=AI、2=人类）；23 号只用类型判定模式，不读头像。`GetResult` 写 `param_1[0]=1`、`[2]`=得分(`+0x4c`)、`[4]`=评级(`+0x6c`)、`[5]`=得分（该副本主程序对 0x17 事件不读）。主程序 `FUN_0050e300`（事件 0x17）：

1. 文案 `string[0x14c8]`(=5320)“%s玩踩蛋小遊戲，獲得%d點券”；
2. **点券 = 得分**：`FUN_00484890(7, 得分, 1)` → `Role_AddTicket`，上限 9999；
3. **卡片**：得分 ≥160 → 卡片索引 0x30；150~159 → 0x2e；其余无（索引=卡表下标，按 card.bin 顺序，推测 Id=索引+1：0x30=Id49 隱形卡，0x2e=Id47 鑽石卡）；
4. 评级 0/1/其它 → 台词类别 4/1/2（消息 0x5a）；
5. `FUN_004aa5d0(6, 得分)` 更新该游戏个人最高分（上限 9999）。

奖励只发给当前玩家（踩蛋人）。

### 5.5 AI 玩家

AI 不运行 DLL：`AI_OnLandEvent@004f79c0` 对 0x17 调 `FUN_004fcb10`，按 `difficuty`（init.txt，本机 3，`FUN_00401060(7)`）随机：`<3` 时 得分 = (rand%10+1)×10（10~100），否则 (rand%8+3)×10（30~100）；点券 `FUN_00484890(7,得分,0)`，文案同 5320，无卡片。

## 7. 未解读 / 推测汇总

- “落地蛋堆”(`+0xd8`)的完整作用：落地蛋让踩蛋人落到蛋堆顶(`CollideEggs` 末尾)；蛋堆升高会清除管子可用标志并可能提前结束，但触发条件未验证。`PipeEggMgr_Update` 里 `+0xf4/+0xf8` 的 1.0/1.5 秒计时与“蛋堆≥2 个且最后两蛋水平距离≤37×缩放”的分支只读到结构，语义未确认。
- 精灵 ID ↔ 贴图、音效 ID ↔ 文件的映射、0x93/0x94/0x95/0x96/0xab/0x80 对应方向键/Enter/ESC，鼠标位掩码 0x40/0x400 对应左键，均为推测。
- 主程序卡片索引→Id 为推测。

## 8. 推翻的上一版结论

1. “玩家通过**旋转蛋人**并击中随机出现的蛋”——没有旋转操作。玩家控制的是在底部中央原地跳跃的踩蛋人（鼠标左键），蛋由左右两根管子水平射出，玩家从上方踩中。
2. “蛋对象：6 个蛋位置；蛋人由 6 个蛋对象组成并分布在圆周上”——不存在。`6` 是踩蛋人 `+0x80` 初值（只减不读）；“圆周”是 `PipeEggMgr_Draw@10038250` 中给第三向量实体临时加的螺旋偏移（调试变量 oldPos/oldAngle，绘制后还原）。
3. “旋转角度存 `DAT_100af640`，旋转速度=参数×50”——`DAT_100af640` 是**管子晃动相位**，每帧 `+= dt×50×方向键速率`，与玩家操作踩蛋人无关。
4. “击中一个蛋加 1 分（`10043d80` 查询得分）”——每踩一个蛋 **+20（左管蛋）或 +10（右管蛋）**；`10043d80` 是 GetResult（写结果结构并清理），不是查询；`10044810` 只是 `+0x4c += x`。
5. “←(0x93) 左旋、→(0x94) 右旋、空格/鼠标点击踩蛋、ESC 退出(`100440e0`)”——键码含义/作用全错：0x93/0x94 是（推测）↑/↓，由第二名玩家用来**摇晃管子**；空格/0xab 只用来关闭说明面板；鼠标左键=起跳；`100440e0` 是关闭说明面板，ESC(0x80，推测)在 `10043e90` 里置结束标志。
6. “`10043ca0` 每帧更新 FPS，249ms 更新一次计数，`counter += score/0.25`”——是方向键**按键速率**统计（每 ≥250ms 速率 = 计数/0.25），与 FPS、得分无关。
7. “游戏时间推测 30~60 秒，未见明确限制”——明确为 **60.0 秒**（`+0x04` 初值 0x42700000）。
8. “蛋的 X/Y 随机范围 (rand%400-400)×scale、(rand%200-200)×scale 是蛋的生成位置；`1003ab00` 蛋生成”——它们是落地蛋堆首次出现时的随机**初速度**；蛋的生成函数是 `FireLeftPipe@10039fe0`/`FireRightPipe@1003a200`（`1003ab00` 是落地蛋物理）。
9. “重力在 `10043850` 计算；`1003a420` 蛋更新”——`10043850` 是 `Update` 主入口，`1003a420` 是管子逻辑；重力基数是 `game+0x48 = 5000×缩放`。
10. 虚函数表“0x54 OnCreate / 0x58 OnDestroy / 0x5c OnUpdate / 0x60 OnDraw / 0x64 OnMessage / 0x68 GetScore / 0x6c Tick”——游戏对象虚表只有 8 项(+0x00~+0x1c)，见 §5.2；上述偏移不存在，列出的 `100623d0`(“OnDraw”)是 UI 库的分组框绘制。
11. “游戏对象结构 +4 score、+8 timeElapsed、+0x20 eggCount、+0x2c eggMan”——实际 +0x04=剩余时间、+0x4c=得分、+0x20=结束标志、+0x2c=说明面板控件。
12. “DAT_100af688 蛋人单例、DAT_100af680 游戏对象单例、DAT_100af640 蛋人旋转角度”——分别是 `PipeEggMgr`、`ShakeMeter`、管子晃动相位；游戏对象单例是 `DAT_100af684`。
13. “音乐 L001.mp3，音量约 0.2，加载 `thunk_FUN_1003b1b0()` 返回音乐管理器”——`1003b1b0` 是 ShakeMeter 访问器；`L001.mp3` 因主程序 `+0x100` 恒返回 -1 而不会播放，真正 BGM 由 `+0x108(0x1a,0)` 触发。
14. “蛋人图片资源 0x7df~0x7e3 = 蛋人”——对应关系成立（实为踩蛋人/小丑的 5 个动作），但“蛋人”应理解为小丑；其余 UI 精灵范围描述 0x852-0x85e/0x834-0x83e/0x83f-0x849 是公共 HUD 数字，不是“UI 元素图片”泛称。
15. “游戏 6=踩蛋的角色？”——已核实为是（见 §1）。
