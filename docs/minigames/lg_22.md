# 大富翁8 小游戏 22 - 分裂球 (Blastomere) 逆向文档

对象：`Gamelib\ltlgame_22.dll`（地图事件 0x16 = 22）。文中地址：`10xxxxxx` 为 DLL 内地址，`00xxxxxx` 为 RichMan8.exe 地址。
标注约定：未标注 = 有反编译/反汇编直接依据；**[推测]** = 间接推断；**[未核实]** = 没有查到。
对应命名表：`<workspace>\out\names_llm\lg_22.tsv`（170 张卡片全部覆盖）。

## 1. 一句话概括

玩家控制屏幕下方的小炮（A/D 移动，空格发射），炮弹击中小球会让它分裂成两个，场上球掉到地面一个得 1 分；限时 50 秒（时间到后不能再发炮，但场上剩余的球继续落地计分），得分上限 999，主程序按分数发放"点券"和卡片。

游戏内说明文字（string.bin 6955，`out\config_utf8\string.bin.txt`）与代码完全吻合：
"一、〔string.bin#6955〕，A左移，D右移，〔string.bin#6955〕。二、〔string.bin#6955〕，〔string.bin#6955〕。三、遊戲時間為50秒。"
另有 6976："〔string.bin#6976〕，〔string.bin#6976〕，注意，〔string.bin#6976〕。"

## 2. 玩法

对象与链表（管理器对象 `DAT_10049068`，构造 10007fa0；游戏主对象 `DAT_10049060`，构造 10003970）：

| 链表 | 位置 | 元素 | 含义 | 依据 |
|---|---|---|---|---|
| A | 管理器+0x18（结构+0x14） | 0x48 字节 | 基本球（虚表 1003e338） | 8780 生成；10009690 触底得分 |
| B | +0x28（结构+0x24） | 0x4c 字节（+0x48=道具类型） | 彩色道具球 | 10008890 生成；击中后触发效果 |
| C | +0x38（结构+0x34） | 0x48 字节 | 炮弹 | 10008390 发射 |
| D | +0x48（结构+0x44） | 0x4c 字节 | "消失一半小球"产生的特效球 | 10008c90 case 7 |
| 飘字 | +0x58（结构+0x54） | 16 字节 | 得分 +1 飘字（寿命、上浮 50px/s） | 10006660 / 10005b70 |
| 玩家炮 | +0x64 | 基对象 | 小炮；速度 +0x88 由按键设定 | 10009380 / 10009690 |

流程：
1. 开局（Manager_InitGame 100091e0）在屏幕上方中央生成第一个球（调用 10008780，方向 0，无水平速度）。
2. 球受重力下落，碰上边/左边/右边反弹（球类虚表 slot0 = 10003d10：状态码 0→反转 vy，2/3→反转 vx），碰到下边界（状态码 1，1000a360 判定）则被删除并计分。
3. 炮弹（链表 C）与球（A）矩形相交（10003c40 → 10003d90）：播音效 0x13f，调 SplitBall（10008a60）在原位置生成两个新对象（一个向左 vx=-100，一个向右 vx=+100，初始上抛 vy=-300），原球与炮弹删除（10009400）。球数因此不断增加。
4. 炮弹与道具球（B）相交：播音效 0x140，触发道具效果（10008c90），道具球与炮弹删除。
5. 炮弹碰到任何边界即被删除（炮弹基类虚表 slot0=1000a4e0 不反弹）。
6. 球管理器更新（10009690）在 A、B、D 三个链表同时为空时返回 1，游戏机进入结算。由于第一个球若未被击中也会落地，如果在 50 秒内球全部落光（例如一开局就让唯一的球落地），游戏会提前结束，得分极低。

分裂时新对象的种类（10008a60，用 `rand()*3.051851e-05` 即 rand/32768 与 0.03、0.13 比较，**每个新对象独立抽取**）：
- 约 3%：特殊道具，类型 6 或 7（rand&1 决定）；若类型 6 且场上球数 >= 0x97(151) 则改为普通球。
- 约 10%（0.03~0.13）：道具类型 0~5（rand%6）。
- 其余约 87%：普通球。
（概率由浮点比较推出，边界处理略有不确定，**[推测]** 精确到百分之一。）

## 3. 操作

按键由主程序经 DLL 虚表 slot4/slot5 传入（见 7.1）。DLL 比较的是小写 ASCII/字符码，主程序传入码的映射**[未核实]**。

| 键码 | 状态 | 作用 | 函数 |
|---|---|---|---|
| 0x20 空格 | 状态0（说明界面） | 开始游戏 | 10003b10 → 100018b0 |
| 0xab | 状态0 | 提交秘籍缓冲并开始游戏（普通开始同样可用） | 10003b10 |
| 0x8c | 状态0 | 清空秘籍缓冲并进入"键入"状态(0x3cc=1) | 10003b10 |
| 其它键 | 状态0 | 追加到缓冲 this+0x3d0 | 10003ac0 |
| 鼠标点击 UI 按钮(ID 2) | 状态0 | 开始游戏（回调 10002460 → 100018b0） | 10002460 |
| 0x61 'a' 按下/松开 | 状态2 | 向左移动(速度 -0x18c)/停止 | 10009380 / 100043b0 |
| 0x64 'd' 按下/松开 | 状态2 | 向右移动(速度 +0x18c)/停止 | 10009380 / 100043b0 |
| 0x20 空格 按下 | 状态2 | 发射炮弹（受射击间隔限制）并置连发标志 0x1b0 | 10009380 |
| 0x20 空格 松开 | 状态2 | 清连发标志 | 100043b0 |

- 状态2 且 `this+0x39c > 0` 时才处理游戏按键（10003b10 / 10001f40）。时间耗尽后 10009690 会清左右按键标志与速度。
- 玩家炮的左右范围由 1000a360 的边界夹紧；初始移速 300（×屏幕缩放，100091e0）。
- 鼠标、虚表 slot6/slot7 在本游戏里是空实现（10001160/10001170 都是 `xor al,al; ret`）。
- 秘籍 "peng"：状态0 下 `0x8c`, `p`,`e`,`n`,`g`, `0xab` → 缓冲恰为 4 字节 "peng" 时调用 10004510：基础射击间隔 0x168 置 0.2f，连发使能 0x1ac 置 1.0f，并在画面上显示 "Cheating......"（10001f70, 标志 0x3cd）。效果是自动连发 + 更快射击，**不是**无限时间。连发代码在 10009690 开头：`0x1ac!=0 && 时间>0 && 0x1b0!=0 && 0x178<0 → FireBullets`。

## 4. 计时（单位：秒，假设宿主传入 dt 为秒，**[推测]** 但与 50.0、倒计时数字吻合）

| 项 | 偏移 | 初值 | 出处 |
|---|---|---|---|
| 游戏时间 | 0x39c | 50.0 (0x42480000) | 100029a9 |
| 开场倒计时 | 0x3a0 | 2.0 (0x40000000) | 100029b3 |
| 结算延迟 | 0x3a4 | 1.0 (0x3f800000) | 100029bd；状态3→4 时再置 1.0 |
| 基础射击间隔 | 管理器+0x168 | 0.4 (0x3ecccccd) | 100091e0（秘籍改为 0.2） |

状态机（Update，虚表 slot2，10001dd0；状态变量 `this+0x2cc`）：
- 0：说明界面（lg_blastomere.ui），等开始。
- 1：开场倒计时，每帧 `0x3a0 -= dt`，`<0` 后转状态 2（绘制端在 >1.0 / <=1.0 时画两张不同的倒计时图，播音效 0x165）。
- 2：每帧 `0x39c -= dt`；`<0` 时置 0，播音效 0x130（一次，0x3b0 标志）；调用管理器更新 10009690，返回 1 → 状态 3。剩余 <=6 秒时 HUD 计时数字换成红色精灵集（10001f70），最后 5 秒在屏幕中央画大号数字并每秒播 0x12f。
- 3：`0x3a4 -= dt` 到 <0 → 状态 4，并重置为 1.0。绘制端在 0x39c<=0 画"时间到"（0x364/0x368），否则画"全部消灭"类横幅（0x35c/0x360）**[横幅含义推测]**；首次进入时按得分档播音效。
- 4：`0x3a4 -= dt` 到 <0 → `this+0x2b8=0` 并返回 false，主程序据此结束小游戏。
所以从开始到结束约 2 + 50 + 球落光所需时间 + 2 秒。

## 5. 计分

- 得分变量：管理器 `+0x16c`（计数），每帧同步到游戏对象 `+0x394`（10009690，地址 1000986a..1000987b）。**不是**旧文档所说的 0x390（0x390 是浮点 Y 坐标）。
- 规则（10009690 中对链表 A 的循环）：A 中元素的 `+0x44`（边界状态码）不为 -1 时删除该元素；球类虚表 slot0（10003d10）已把状态 0/2/3 复位为 -1，只有触底状态 1 会保留，所以"球触底 = 删除并 +1 分"。该处同时：压入飘字（16 字节：位置 + 寿命 1.0f），`+0x16c = min(+0x16c+1, 999)`。
- 上限 999（`if (999 < n) n = 999`）。
- 没有任何"时间奖励/碰撞次数"项；击中、分裂、拾取道具本身不加分；道具球(B)落地、炮弹出界、链表 D 球消失均不加分。
- 分档（用于结算图/音效，同时作为 GetResult 的 `field3`）：
  - 得分 < 0x33(51)，即 0~50：档 0，音效 0x135，结算图 0x36c。
  - 0x33 <= 得分 < 0x97(151)，即 51~150：档 1，音效 0x134，结算图 0x374+0x370。
  - 得分 >= 151：档 2，音效 0x15c，结算图 0x378。
  （10001f70 的 case 3 / case 4）
- 难度：游戏内无难度分级。宿主传给 DLL 的 `this+0x2ac`（= `FUN_00401060(7)<<1`，见 7.2）在游戏代码区（10001000~1000b000）没有任何读取。唯一影响难度的是道具与球数（见 6）。

### 7.2 init 参数（0x2ac 字节，init 内 `rep movsd 0xab` 复制到 this+8，同时保存指针到 this+0x2b4）

由 00510e90 构造：
- `+0x00` 玩家数 = max(人类玩家数, 2)（其余槽位用随机 NPC 填充）。
- `+0x04 + i*0x54` 每名玩家 0x54 字节：`+0` 玩家 id（来自玩家表项 +1 的值），`+4` 名字串(0x40)，`+0x44` 类型(1 或 2)，`+0x48` 头像贴图句柄（`texture\prt\npc\%s_01`），`+0x4c` 角色 +0x308，`+0x50` 标志。
- `+0x2a4` = `FUN_00401060(7) << 1`，`+0x2a8` = 1。（`FUN_00401060(n)` 只是 `*(table+n*4)` 的取值函数，table 来源**[未核实]**，可能是难度/设置项。）
- 本 DLL 只读取玩家数（this+8）与每个玩家的 id（`this+0xc+i*0x54`，仅在 GetResult 中回写）。

宿主服务对象（CMiniGameHost_2，虚表 005e8928，`this+4`；偏移 = 索引*4）本游戏用到的项（实现函数见 `<workspace>\tmp_sonnet\hostapi.txt`）：
0x50 按资源 id 加载精灵(0050f750)；0x54 释放(0050f7a0)；0x58 设动画/状态(0050f800)；0x64 设缩放；0x68 设位置；0x78 精灵按 dt 更新(0050faa0)；0x7c 绘制精灵(0050fad0)；0x108/0x110 显示参数；0x114 播放音效(逻辑音效 id, 位置向量, 音量, 标志)(00510c30)；0x120/0x124 取窗口宽/高(00510bb0/00510bf0)；0x130 设置光标显示(00510a90→00407600)；0x13c UI 管理器指针(DAT_006570d8)；0x140 取游戏根路径；0xfc 取字符串表第 n 项(00510db0)。
（其中 0x64/0x68/0x6c/0x90 等精确语义以调用上下文推断**[推测]**。）

### 7.3 结果结构（GetResult 写入，100034b0）

```
int  count;                 // = 玩家数 (this+8)
struct { int id; int score; int flagA; int field3; int flagB; } e[count];   // 每项 20 字节，起始于 out+4
```
- `e[i].id` = 对应玩家描述的 +0 字段。
- `e[0].score` = `this+0x394`（得分）；其余玩家 score = 0。
- `e[i].flagA` = 0；`e[i].field3` = `this+0x398`（分档 0/1/2）；`e[i].flagB` = `e[i].score`。
- 0050e300 对事件 0x16 只使用 `e[0].score`（`aiStack_b0[1]`）与 `e[0].field3`（`aiStack_b0[3]`），不使用 id（奖励给"当前回合玩家" `DAT_00632dac[0xb]`）。

### 7.4 主程序如何据分数发奖励（0050e300，`in_ECX+4 == 0x16` 走通用分支）

1. 文本串：`FUN_0040e2f0()` 串表第 `0x16+0x14b0` 项，因为 `>0x14c5` 再 +1 → 0x14c7 = 5319："%s玩分裂球小遊戲，獲得了%d點券"（参数 = 当前玩家名 + 得分）。
2. 仅当 `score > 0` 才发奖励。
3. `FUN_00484890(7, score, 1)`：命令 7 → `FUN_00489ed0(score, 0)`，给当前玩家 `+0x324` 加分（上限 9999），即"点券"。
4. 卡片（命令 4 → `FUN_00488e80(idx,0)`，参数是 card.bin 下标，Id = 下标 + 1；旧版把下标当 Id，卡名写错，已更正，见 port.md §3.1）：
   - `score < 999`：`score >= 150`（代码 `0x95 < score`）→ 下标 0x2c = Id 45 老千卡。
   - `score >= 999`（即达到上限）→ 老千卡(0x2c) + 下标 0x2f = Id 48 地王卡 + 下标 0x12 = Id 19 核子飛彈。
   注意 DLL 内部"高档"从 151 开始，主程序发卡从 150 开始，相差 1。
5. `FUN_00484c30(n)`（= 命令 0x5a，`FUN_00490f40(n,0)`，含义**[未核实]**，可能是角色反应动画）：`e[0].field3` 为 0 → n=4；1 → n=1；其余 → n=2。
6. `FUN_004aa5d0(0x16-0x11 = 5, score)`：更新统计对象 `+0x840+5*4` 处的该小游戏最高分（取最大，上限 9999）。
7. 之后释放宿主对象、`FreeLibrary`。

### 7.5 AI 玩家

AI 不进入游戏。`FUN_004f79c0` 的 case 0x12~0x17 先调 `FUN_004fcb10(eventId)`：事件 0x16 时 `v = FUN_00401060(7)`，`v < 3` → `score = rand()%0x78 + 1`（1~120）；否则 `score = rand()%0xb4 + 0x14`（20~199）。随后以同一条文字 5319（索引 0x14c7）提示，并 `FUN_00484890(7, score, 0)` 加点券；**不发卡片**，也不更新最高分。`FUN_004fcb10` 对事件 0x16 无"存在真人则改为实际游戏"的判断（仅事件 0x15 有）。

## 11. 推翻的上一版结论

上一版 `lg_22.md` / `lg_22.tsv`（较弱模型）：
1. "弹珠/物理碰撞游戏，玩家控制一个主球"→ 实为**小炮打小球**：玩家控制炮（A/D/空格），球是被打的目标。
2. "状态1 初始化 → 立即转状态2"→ 状态1 是 2.0 秒开场倒计时（0x3a0=2.0），不是立即转移。
3. "初始时间推测 10~15 秒"→ **50.0 秒**（100029a9）。
4. "得分 = 碰撞次数×基础点值 + 剩余秒数×倍数"、"时间<=6.0 使用特殊计分"→ 完全不存在；得分只有"球触底 +1"，上限 999；<=6 秒只是计时数字改用红色精灵。
5. "得分存于 0x390，0x394 为临时分数"→ 0x394 才是得分，0x398 是分档；0x390 是浮点 Y 坐标。
6. "作弊码 peng 设置时间为无限(0x3f800000=1.0)"→ 实际设基础射击间隔 0.2、连发使能 1.0，画面显示 "Cheating......"，与时间无关；0x8c/0xab 也不是"菜单操作/特殊输入"，而是秘籍输入起止（0xab 同时可开始游戏）。
7. "FUN_1000adb0 = LG22_Score_Calculate（分数计算）"→ 它是 UI 控件基类析构（vtable PTR_LAB_1003e418），旧命名错误；同类错误：LG22_Game_Logic(10019370)、LG22_Score_Display(100197d0)、LG22_Time_Management(10019910)、LG22_Render_Pipeline(1001df00) 等 1000a660 之后的函数全是 UI 控件库，不是游戏逻辑。
8. "FUN_10008a60 随机生成 8 个方向分裂"、"FUN_10003c40 生成 8 个随机坐标"→ 分裂只产生左右两个新对象（vx=∓100）并抽取是否带道具；10003c40 只是把 8 个 float 转 int 后做矩形相交。
9. "旧虚函数表（0x50 加载资源、0x54、0x68…0x200）是游戏对象的虚表"→ 那些是**宿主服务对象**（CMiniGameHost_2，005e8928）的接口；游戏对象自己的虚表只有 8 个槽（init/GetResult/update/draw/key/keyUp/空/空）。
10. "主程序读 0x390 得分、调用 LG_delete_game 后给奖励"→ 主程序在 0050e300 先调 slot1 GetResult（读 0x394/0x398），再 LG_delete_game；奖励是点券(命令7) + 卡片(命令4) + 最高分记录，不是单纯"按分数给奖励"。
11. "图片ID 0x82/0x84/0x85…（UI）"→ 实际精灵 id 为 0x76d~0x784、0x834~0x85f、0x6ba，UI 贴图号 463~475、786/787、976。
12. "BlastScoreLog.txt 游戏结束时写入最终分数"→ 写文件函数 10001b60 存在，但无任何调用，不会写。
13. "道具/彩色球/多球机制未提及"（旧文档完全遗漏）→ 补充了 8 种道具及概率、球类/道具类/炮弹/特效球的链表结构。
14. 旧 tsv 中的 Explosion_*/Spark_*/Trajectory_* 等"爆炸/火花/轨迹"命名无依据：实际 A/B/C/D 是 球/道具球/炮弹/特效球 链表，已全部改名；旧 tsv 里 85 个 H 中绝大部分无直接证据，已降级。
