# 大富翁8 存档格式 (record_*.sav)

写档函数 `FUN_004a7540`，读档函数 `FUN_004a78f0`；解析器 `scripts/savefile.py`。移植的实现（读写这个格式 + 扩展块、静止点、对应关系、验证）见 `docs/save_port.md`；新增事实：槽位头里 `+2/+6/+8/+10` 是 SYSTEMTIME 的月 / 日 / 时 / 分（`+0` 年），street 记录按 street.bin 的节顺序而不是 ID，地块记录按各地块最小道路格排序，`record_m01.sav` 是自由模式样本（setup 标志 0、无 sflb 段）。

约定：
- 所有整数小端。"写入" 指 `FUN_0051e270(stream, buf, n)` (RwStreamWrite)，"读取" 指 `FUN_0051e120`。
- "依据" 列给出做这次写入的函数地址（`this+0x..` 为对象成员偏移）。读档对照函数在各节标题里注明。
- 含义列标记：无标记 = 代码里有直接证据；**(推测)** = 只有样本数据证据；**(未知)** = 不知道。
- **Ghidra 反编译会丢掉 `FUN_0051e270` 的参数**（例如 `FUN_0051e270(param_1);` 实际是 `push 4; push this; push stream`）。
  所以每一次 I/O 调用的大小和缓冲区都用反汇编核对过（`scripts/exe_dis.py`、`scripts/exe_io.py <地址>` 会列出函数里每次
  RwStreamWrite/Read 的 size 和缓冲区表达式）。
- 偏移列：绝对偏移取自 record_01.sav（2 人局）；含可变长度的段，之后的偏移随内容变化，所以多数表给“段内相对偏移”。

## 无法仅凭存档得出的两个计数（外部依据）

存档里**没有**写入地块数和奇迹数。读档 `FUN_004a78f0` 在读这一段前已经用 `FUN_004a31f0 → FUN_004a33d0` 按 header 的地图编号
载入 `Map\NN.map` 并建好地块对象；`FUN_004f2c20` 的两个循环次数就是这些容器的计数 (`TerraMgr+0x1c`、`TerraMgr+0x3c`)。
解析器因此读取同目录结构下的地图文件来得到这两个数（`--game-dir` 指向 `RichMan8` 目录，默认取存档的上上级目录）：

- 地图文件 (`FUN_004a33d0` / `FUN_00420f90`)：`"rch8map\0"`(8) + 版本(4) + 0x3c 字节头（起始 2 个 int = 宽、高）
  + (宽+1)×(高+1) 个顶点 × 0x14 字节（`FUN_0042ae80`，每顶点读 5 个 int）
  + 宽×高 个 cell × 0x1c 字节（`FUN_00420530`，每 cell 读 7 个 int：cell+0x2c, +0x3c, +0x44, +0x48, +0x60, +0x1c, +0x34）+ 其余场景数据。
- `FUN_004f07d0` 遍历 cell 调 `FUN_004f1320`；cell+0x2c≠0 时：`(cell+0x44)&0xff ∈ {1,2}` → `FUN_004f1680`
  按 cell+0x40 去重各建一个 Terra；`∈[4,9]` → `FUN_004f1820` 按 cell+0x40 去重各建一个 Wonder。
- cell+0x40 是加载时由 `FUN_00424e50` 给同一次放置的所有 cell 赋的同一个值；文件里同组 cell 共享 +0x48（组首序号，
  `FUN_00420f90` 末尾用 `cell[0]==cell[+0x48]` 判组首）。解析器用文件里的 cell+0x48 去重，等价于按 cell+0x40 去重。
- 结果：map 3（巴黎）= 39 个地块 + 1 个奇迹；map 10（〔string.bin#3826〕）= 41 个地块 + 1 个奇迹。这两个数独立于存档推出，
  然后在 4 个 map3/map10 样本上都使后续各段恰好对齐到文件末尾，并通过合理性自检。
- 目前只支持 stage.bin 里 id 1..11 的地图 (`Map\NN.map`)；下载地图（id≥21）或缺地图文件时解析器在 terra 段起点停止，
  报告 `unparsed_from`。

另一个由游戏数据决定的常数：街道数 = `street.bin` 的节数 137（`FUN_00404080 → FUN_0042d210` 把每个节压入街道容器；
`FUN_0042d8b0` 从下标 1 循环到计数−1，即 136 条）。样本中 2176 = 136×16 字节吻合。

角色数不在文件里单独写，依据：`FUN_004a78f0` 对 setup 数组的每个元素调一次 `FUN_004a3760 → FUN_00495f60` 创建一个角色，
所以 `角色数 = setup.count`（= header.player_count），第 i 个角色对应第 i 个 setup 元素。
