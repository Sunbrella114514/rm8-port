# 大富翁8 配置文件格式分析

## 文档说明
本文档对 RichMan8（大富翁8）游戏配置目录下的 .bin 文件进行逆向分析。这些文件原本为 Big5(cp950) 编码的明文 INI 格式，以字节加法循环密钥 "tiep8jdg" 加密。本分析基于已解密并转换为 UTF-8 的文本版本。

---

### 字段详解

| 字段 | 含义 |
|-----|------|
| Id | 角色编号 1~16（pass 文件 role 字段、脚本中的角色号均以此为准；脚本运行时的 `curRole` 是本局座位号 0~3，不是这个 Id） |
| sex | 0 女 / 1 男（影响通用语音选择，推测） |
| scale | 4 个缩放值，所有角色相同 |
| offset | 3 个浮点数，模型位置偏移（推测 X/Y/Z） |
| artId1 / artId2 / artId3 | 每组 4 个模型/动画编号。**推测 1/2/3 分别对应 步行/机车/汽车 三种交通工具**（与卡片 ChgTrfTool 1/2/3 一致），每组 4 个对应不同动作 |
| dicePos1/2/3 | 三种交通工具下骰子出现的位置 |
| wlkSndId | 3 个脚步/引擎音效编号（对应三种交通工具，推测） |
| speed | 3 个移动速度，对应三种交通工具（推测）；金貝貝 100/120/140 最慢，星期三步行 160 最快 |
| strId | 该角色台词/名称在 string.bin 中的起始编号，间隔 200 |
| picName | 头像贴图 p_01~p_16 |
| AI | 绑定的 AI 脚本（Pysrc/AI_xx.pyc） |

### 修改建议
- `speed` 只影响走路动画速度（推测），不影响步数与胜负，可放心调快以缩短对局时间。
- `AI` 可以换成其他 AI 脚本，比如把弱 AI 角色绑定到 AI_01（详见 ai.md）。

## 2. 股票配置 (stock.bin.txt)

### 用途（主代理已核实）
144 支股票的定义。每局可交易的股票 = **〔string.bin#7051〕的 12 支 + 通用的 10 支**，共 22 支。
依据：存档 `record_01.sav` 头部的地图号为 3（巴黎），存档内正好有 22 条股票记录，即 c=3 的 12 支加上 c=100 的 10 支。

### 字段详解

| 字段 | 实际取值 | 含义 |
|-----|------|------|
| 节名 | 公司名 | 股票名（Big5，存档里也以此名保存） |
| c | -1 / 0 / 1~11 / 100 | **所属地图**：1~11 对应 stage.bin 中的地图 id（每张 12 支）；100 = 通用股（10 支，所有地图都有）；-1 電力公司、0 點券中心 为特殊条目（推测对应地图上的电力公司/点券中心建筑，不在股市中交易） |
| initprice | 10~180（众数 100） | 开局股价（元），实际价格可能还要乘以物价指数 `Role.PriceIndex()`（推测） |
| totalnum | 全部 10000 | 发行总量（AI 用 `Stock.FlowSum` 读取流通量） |
| vivacity | 0.5~1.8 | 活跃度/波动系数，越大涨跌幅越大（推测）；最大 1.8：黑幫油漆、足球餐廳 |
| id | 0（139 支）/ 1（5 支） | 含义待验证 |

### 修改建议
- 想让股市更刺激：提高 vivacity（例如 ≥1.5）；想更稳：降到 0.5~0.8。
- 想降低开局门槛：调低 initprice。
- 新增股票时 c 必须是有效的地图号或 100；每张地图的股票数量是否允许超过 12 支需要验证（存档中股票记录为定长 0x37C 字节）。

## 3. 关卡配置 (pass_01.bin.txt ~ pass_16.bin.txt)

### 用途
定义 16 个不同关卡的胜利条件、起始资源、AI 对手选择、奖励等。

### 通用结构
**节名**：城市/地点名称（每个 pass 文件包含 9-10 个关卡）
- 阶段从简到难，level 字段标记难度等级

### 字段详解（主代理已按 16 个文件全量统计核实）

`pass_XX` 共 16 个，与 16 个可选角色（roleinfo.bin 中的 16 节、AI_01~16、sp_01~16）一一对应，推测为**以第 XX 号角色进行闯关/剧情模式时的关卡路线**。每个文件 5~9 节，每节一关，最后一关都是「魔都」（stage=3，level=3，对手 role=16,0,0，即 Boss 角色 16 号；pass_16 中为 -1）。

| 字段 | 实际取值 | 含义 |
|-----|------|------|
| level | 0(16 次) / 1(53) / 2(48) / 3(16) | 关卡阶段：0 起始关、1/2 中段可选关、3 最终关 |
| stage | 1~11 | 地图编号，对应 stage.bin 中 id（1 香港、2 台北、3 巴黎/魔都…，对应 Map/NN.map） |
| role | 如 `9,10,2`，`0` 表示该位置无对手 | 三个电脑对手的角色编号（roleinfo 中 Id） |
| start_cash | 100000(130 次) / 200000(2) / 300000(1) | 起始现金 |
| start_fund | 100000(132) / 200000(1) | 起始存款（银行），AI 中的 `Role.Fund` |
| start_ticket | 50(131) / 100 / 200 | 起始点券 |
| start_card | `卡Id,卡Id`，`0` 为空 | **起始赠送的卡片 Id**（不是数量），例如 45=老千卡、7=机车卡、18=飞弹卡 |
| start_pic | 两个编号 | 推测为起始拥有的图片/图鉴编号（待验证） |
| reward_cash | 0 / 100000 / 200000 | 过关奖励现金 |
| reward_tichet | 0 / 100 | 过关奖励点券（原文拼写如此，修改时必须保留错误拼写） |
| reward_card | 最多 4 个卡 Id | 过关奖励卡片 Id，如 `16,17,18,19` |
| reward_pic | 两个编号 | 过关奖励图片编号（推测解锁图鉴/CG） |

### 修改建议
- 想降低难度：提高 `start_cash/start_fund/start_ticket`，在 `start_card` 中放强力卡（如 32 竹蜻蜓、48 地王、49 隐形）。
- 想提高难度：减少起始资金，或在 `role` 中把 0 换成对手编号以增加对手数量。
- `role` 中的编号需要是存在的角色（1~16），否则行为未知。
- 修改后用 `rm8crypt.py encutf8 auto xxx.bin.txt xxx.bin` 转码并加密回 `.bin`。

## 4. 舞台配置 (stage.bin.txt)

### 用途
定义 11 个〔string.bin#6203〕舞台，关联地图文件、奇迹位置、气候等。

### 结构
**节名**：城市名称（共11个）：香港、臺北、巴黎、東京、阿拉伯、上海、拉斯維加斯、好萊塢、夏威夷、澳大利亞、...

### 字段详解

| 字段 | 类型 | 取值范围 | 含义 |
|-----|------|---------|------|
| id | 整数 | 1-10 | 舞台唯一ID |
| mapfile | 字符串 | "01.map" 到 "10.map" | 地图资源文件名（.map 格式） |
| wonder | 整数数组 | 如"641,643,645" 或 "-1,658,-1" | 三个奇迹位置的美术资源 ID（-1 表示该位置无奇迹） |
| clime | 整数 | 1, 2, 3 | 气候类型（推测：1=温带， 2=沙漠， 3=特殊） |

### 统计数据
- **wonder 字段**：
  - 多数关卡3个奇迹（如香港、臺北、上海）
  - 部分关卡2个奇迹（如巴黎、東京、夏威夷）
  - 所有值在 600-700 范围内（美术资源ID编号方案）
  
- **clime 分布**：
  - clime=1（温带/城市）：香港、臺北、東京、上海、好萊塢 等 5 个
  - clime=2（沙漠）：拉斯維加斯（1个）
  - clime=3（特殊）：巴黎、阿拉伯、夏威夷、澳大利亞 等 4 个

### 修改建议
**优先级低**（视觉相关）：
1. **clime** - 影响地图渲染风格（天空颜色、背景等）
   - 建议：无需改动，保持游戏美术一致性
2. **wonder** - 可以改变奇迹的可见性/位置
   - 建议：若要调整奇迹难度，可修改对应的美术资源ID范围

## 6. 街道配置 (street.bin.txt)

### 用途
定义 137 条街道的〔string.bin#1〕。

### 结构
**节名**：街道名称（包括空地 " "）

### 字段详解

| 字段 | 类型 | 取值范围 | 含义 |
|-----|------|---------|------|
| ID | 整数 | 0-136 | 街道唯一ID |
| price | 整数 | 80-160 | **街道系数（%）**，已由 exe 验证：住宅租金 = RentTable[等级] × price/100 × 物价指数（见 exe_internals.md §4.5），购地价格同样乘这个系数。节按地图顺序排列（ID 0 为空名占位） |

### 统计数据
- **price 范围**：
  - 最低：80
  - 最高：160
  - 典型分布：80, 90, 100, 120, 140, 160 元（似乎有固定等级）

### 修改建议
**优先级次高**：
1. **price** - 影响初期投资策略和游戏经济平衡
   - 建议：可按连通性调整，使所有价格区间都有策略价值
   - 例如：当前 80 元街道过多，建议将部分改为 100-120 元

## 8. 其他配置文件

### 8.1 路线配置 (route.bin.txt)
**用途**：定义 8 条公路线路的颜色渲染参数
**字段**：filename(route_00-07), red/green/blue (RGB 颜色值，全部为 60=暗灰色)
**修改建议**：可调整 RGB 值改变路线外观，但对游戏玩法无影响，优先级低

### 8.2 地形纹理 (landtex.bin.txt)
**用途**：定义 20 种地形的美术资源和光照
**字段**：
- filename: Lords_00 到 Lords_19
- light: 140-180（光照强度）
**修改建议**：调整 light 影响地形视觉效果，游戏平衡性无关，优先级低

### 8.3 地产类型 (terra.bin.txt)
**用途**：定义 13 种地块外观类型（主代理核实：共 13 节，id 1~9 为住宅/商业用地的不同尺寸，100~103 为特殊建筑）
**关键字段**：
- id: 1~9、100~103
- size: 1-4（占用地块数）
- artId: 美术资源ID
- filename: 地块资源文件名
**修改建议**：不建议改动，与地图资源耦合度高

### 8.4 NPC 配置 (npcinfo.bin.txt)
**用途**：定义 22 个 NPC 角色及其属性
**关键字段**：
- Id: NPC 编号，与脚本 `Npc.ID()/Npc.Create()` 以及附身编号 `Role.Shape()` 一致（1 财神 … 16 路霸）
- type: 0 神明（附身）、1 地图上的人物/道具、2 放置类障碍（路障/地雷/定时炸弹/机器娃娃）、3 特殊（路霸、踩蛋）、4 小游戏/彩蛋
- date: **持续天数**（推测：神明附身 7 天，土地公/糊涂神/路霸 5 天，0 = 不限）
- artId/artNum: 模型编号及数量；sound: 出现音效
- good: 1 好（财神/福神/土地公/拼图）、0 坏（穷神/衰神）、2 中性
- 修改 date 可以调整神明附身的持续时间（推测，待游戏内验证）
**修改建议**：可调整 good 字段改变 NPC 事件倾向（利好/利空），但需谨慎改动 artId

### 8.5 电影配置 (movie.bin.txt)
**用途**：定义 16 个角色的开始/结束剧情动画
**字段**：
- start_num/end_num: 动画片段数（2-4片段）
- start_X/end_X: 动画文件名（da01_1 等）
**修改建议**：优先级低，修改需准备对应动画文件

### 8.6 路线介绍 (introduce.bin.txt)
**用途**：游戏内景点介绍文本，全部在一个 `[景點介紹]` 节下，按编号 `N=` 列出，每条包含：
- 景点名称
- 介绍文本
- 美术资源ID（如 #641）
**修改建议**：仅涉及内容/文案，可自由修改，需注意 Big5 编码

### 8.7 问卷配置 (questions_normal.bin.txt)
**用途**：定义 201 道答题游戏问题
**字段**：Question, AnswerA/B/C/D, answer（正确答案索引 0-3）
**修改建议**：可修改题目和答案以改变难度，注意答案索引有效范围

### 8.8 节日配置 (festival.bin.txt)
**用途**：定义春节日期表（不是 INI 格式，而是简单数字行）
**内容**：前两行为 `00000006`、`00000032`（推测为表头/条目数 32），之后是 2003~2034 年共 32 个春节日期（YYYYMMDD）。
**注意**：存档显示游戏内的开局日期取自系统当前日期（2026 年）。这张表只到 2034 年，**2035 年以后春节相关事件可能失效**，届时需要补充日期。
**修改建议**：若要改变节日，按格式 YYYYMMDD 添加/删除日期

### 关键格式化占位符

| 占位符 | 含义 | 示例 |

| %d | 整数（数值、金钱等） | "租金：%d元" |
| %% | 百分号（显示为 %） | "20%%" 显示为 "20%" |
| \  | 换行符 | "%s\購買價格%d元" |

### 修改建议
**优先级高**：
1. **文案修改时必须保持占位符数量和顺序不变**
   - 错误示例："%s購買%d元" 改为 "%s購買%d元%d天" (多了一个 %d)
   - 正确示例："%s購買價格%d元" 改为 "%s商品定價%d元" (占位符数量和顺序不变)

2. **新增文本时**：使用新编号，不要在现有编号间插入

3. **删除文本时**：保留条目编号，内容留空或注释，避免破坏ID映射关系

## 10. 对话/演讲配置 (speech/sp_XX.bin.txt 和 drama.bin.txt)

### 用途
定义 16 个角色在各舞台的对话文本和剧情对白。

### 结构

**sp_XX.bin.txt** (16 个文件，对应 16 个角色)：
- **节名**：角色/舞台名称（如 [萊娜]、[錢夫人] 等）
- **字段**：
  - pId: 角色ID（1-16）
  - num: 对话条数（通常 2-3 条）
  - rlId1/rlId2/...: 对话关系ID（指向另一个角色 ID 或特殊值）
  - text1/text2/...: 对话内容（中文字符串）

**drama.bin.txt** （剧情对白）：
- 节名：[编号]（如 [1]、[2] 等）
- 字段：
  - Id: 剧情ID（唯一标识）
  - num: 对话轮数（1-4）
  - rlId1/rlId2/...: 参与人物ID
  - text1/text2/...: 台词内容

### 关键观察

**sp_XX 结构示例**（以 sp_01 为例）：
```
[萊娜]
pId=2
num=2
rlId1=1
text1=嗨美女，讓我來幫你拿衝浪板吧？
rlId2=2
text2=不用了，謝謝你。
```
- 通常 rlId1 指向主角对话者，rlId2 是回应（同一人物时为自言自语）
- num=2 表示两条连续的对话行

**drama.bin 结构示例**：
```
[1]
Id=1
num=4
rlId1=20   # 角色20（讨债人）
text1=看你這次往哪兒跑！快還錢。
rlId2=1    # 角色1（大老千）
text2=大哥你饒了我吧，我現在手頭真的沒錢啊。
rlId3=20
text3=沒錢？沒錢就去給我想辦法借！
rlId4=19   # 角色19（旁白？）
text4=大老千向銀行貸款15萬，用5萬將討債人打發走。
```
- rlId 可能扩展范围（19=旁白、20=债主等）
- num > 2 时表示多人对话或叙述文本

### 修改建议
**优先级中等**：
1. **文本内容修改**：完全自由，只需保证 Big5 编码
2. **角色关系修改**：可改变 rlId，但需确保角色ID有效（1-16 为角色，18+ 为NPC/特殊）
3. **对话数量修改**：可改变 num，对应添加/删除 rlIdX 和 textX 字段

## 修改与打包说明

### 修改工作流程

1. **解密与转换**（已完成）
   - 原文件在 `<old-edition-dir>\Config\*.bin`
   - 已用 tiep8jdg 密钥解密，转为 UTF-8 保存在 `<workspace>\out\config_utf8\`

2. **编辑文件**
   - 使用任何文本编辑器直接编辑 UTF-8 txt 文件
   - **注意**：string.bin 中的 %s、%d 占位符不能改变数量和顺序

3. **重新编码与加密**
   - 一步完成“UTF-8 → Big5(cp950) → 加密”（主代理已验证 113 个配置可逐字节还原）：
   ```bash
   <workspace>\.venv\Scripts\python.exe <workspace>\scripts\rm8crypt.py encutf8 auto 输入.txt 输出.bin
   ```
   - 只有在文件已手动转成 Big5 时才用 `enc`；对 UTF-8 文件直接用 `enc` 会生成乱码配置。
   - 输出文件应命名为原始 .bin 文件名（如 roleinfo.bin）
   
4. **验证**
   - 将加密后的 .bin 文件复制回 `<old-edition-dir>\Config\` 对应位置
   - 启动游戏验证修改是否生效

### 加密脚本调用示例
```bash
# 单个文件加密
python <workspace>\scripts\rm8crypt.py encutf8 auto roleinfo.bin.txt roleinfo.bin

# 批量加密 (所有 pass 文件)
for i in {1..16}; do
  python <workspace>\scripts\rm8crypt.py encutf8 auto "pass\pass_$(printf %02d $i).bin.txt" "pass\pass_$(printf %02d $i).bin"
done
```

### 注意事项
- **编码**：修改前必须保证为 UTF-8，加密前必须转为 Big5(cp950)
- **占位符**：string.bin 修改时特别谨慎，保持 %s/%d 数量和顺序
- **ID 范围**：修改 role 字段时确保角色ID在 1-16 范围内
- **美术资源**：artId 修改需要对应的美术资源文件存在，否则显示异常
- **备份**：修改前备份原始文件
