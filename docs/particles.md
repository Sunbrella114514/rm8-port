# 大富翁8 粒子特效系统（PrtEffTable）逆向说明

本文的目标是让移植版（librw / OpenGL ES）按原版效果重现地图摆件上的粒子，例如魔法屋锅里冒出的气泡。

- 文件格式（逐字节结构）见 `docs/prt_format.md`。本文只讲 payload 字段的含义和运行时算法。
- 解析器、参考模拟器和预览工具：`scripts/prteff.py`。
- 中间产物与验收记录：`out/prt_review/`。

> **核心结论**：游戏的粒子系统没有自己写，用的是 RenderWare 3.7 自带的三个插件：
> - **RpPrtStd**：标准粒子；
> - **RpPrtAdv**：高级粒子，提供多段颜色、UV 步进和球形/圆环发射器；
> - **RpPTank**：广告牌批量绘制。
>
> 游戏代码只负责把 0x160 字节的 payload 翻译成这些插件的"发射器属性"（0x468540 / 0x469900），其余全部由 RW 静态库完成：
> - RW 静态库的地址范围：发射与更新在 0x59C000–0x5A6800，绘制在 0x592E80–0x596800。
> - 反编译里这些 RW 函数的自动命名（`u_UiLib_*`、`u_RW_Mesh_*` 等）全部是错的，以本文为准。

## 0. 结论速览（移植要点）

1. **随机数可以逐位复现。**
   - 每个新建发射器的种子都是 1（0x5A02E0）。
   - LCG 为 `s = s*0xBB38435 + 0x3619636B`，取值 `r = 2*s/2^32 - 1 ∈ [-1,1)`。
   - 每个参数都按 `值 = 基值 + r * 偏差` 计算。偏差是"半幅"，取值区间为 [基值−偏差, 基值+偏差)。
   - 随机数的消耗顺序固定，见 §3.3。按顺序实现后，模拟器输出可以和 C++ 逐帧对拍。
2. **时间单位是秒。**
   - dt 来自主循环：`min((timeGetTime差)*0.001, 0.1)`，见 0x4035E0。主循环限帧约 15 ms。
   - 地图加载完会额外以 dt=1.0 更新一次（0x4A33D0）。
3. **发射与更新的规则：**
   - 每隔 `emit_gap ± emit_gap_bias` 秒发射一批，每批 `emit_num + trunc(r*emit_num_bias)` 个。
   - 存活总数不超过 `max_prt`，超出的部分直接截掉。效果 0 的发射速率是 20 个/秒，而 `max_prt=20`、平均寿命 3 秒，所以大部分时间粒子数卡在上限，新粒子要等老粒子死了才补上。
   - 粒子运动是"先速度后位置"的显式欧拉：`v += F*dt; p += v*dt`。
   - 尺寸、颜色、旋转、UV 都按 `t = 年龄/寿命`（上限钳到 1）做线性插值。
4. **贴图动画不是按毫秒播放的。**
   - uvlist 的帧时长只用作权重：把前 n−1 帧的时长归一化到粒子寿命上，按"步进"切换（不插值）。
   - **最后一帧永远不会显示**。原版数据里 uvlist 9/10 把最后一帧复制了一份，可见作者知道这一点。
5. **绘制方式：**
   - 每个粒子画成一个与相机平行的四边形，中心为粒子位置，宽高为 `size`（整宽，不是半宽）。
   - 屏幕内可以带 2D 旋转，正角度在屏幕上顺时针转。
   - 颜色取 `贴图 × 顶点色`（RGB 和 A 都相乘）。
   - 混合因子 `src_blend/dst_blend` 取 RW 枚举，数值与 D3DBLEND 相同。
   - 开深度测试、关深度写入。
6. **坐标系：**
   - 粒子位置在发射时就变换到世界坐标，之后不随发射器移动。
   - 发射器矩阵每帧复制自父摆件"挂点"所在 frame 的 LTM（世界矩阵，含旋转和缩放）。
   - 挂点号就是该 frame 用户数据串 `[@n]` 里的 n，不是 HAnim 节点号（§4）。

## 2. payload 字段表（0x160 字节，kind=0）

- "读取处"一列写的是最直接的读取点。p[k] 表示 payload 的第 k 个 dword，std 表示 RpPrtStd 标准发射器属性。
- 把握程度分三档：
  - **高**：直接读到代码，并且独立复核或数据验证过；
  - **中**：读到代码，但语义有推断；
  - **未知**：没有找到读取代码。
- 解析器 `prteff.py selfcheck` 已验证：下表与关键帧区恰好覆盖 0x160 字节的每一个字节，没有遗漏，也没有重叠。

- **尺寸属性**：size_end≠size_start，或 end_bias≠start_bias 时才建立。没有尺寸属性时尺寸恒为 size_start，不消耗随机数。
- **旋转属性**：rot_end≠rot_start，或 rot_end_bias≠rot_start_bias 时才建立。没有旋转属性时旋转角恒为 0。

## 3. 运行时算法

### 3.1 创建（SpawnEffect → BuildRender → PlayAnimation）

1. 0x46CFD0 先查该 id 的回收池（记录 +0xC 数组，长度在 +0x10）。
   - 池中有发射器就复用：0x46AE10 重新打开发射标志（flags \|= 8），时长计数清零。**RW 内部状态（种子、粒子、currTime）沿用上次的**。
   - 池中没有就新建 0x24 字节对象，再调用 0x468540 和 0x46AB80。
2. 0x468540 按 payload 组装标志（simple_mode=0 时）：
   - **发射器标志**：基础值 0x21（标准 + PTank）。
     - 颜色键 =2 时加 0x02；≥3 时加 0x202（多一个 0x1000002 多段颜色）。
     - 有尺寸属性加 0x10，有旋转属性加 0x08。
     - 一定加纹理坐标 0x04；UV 帧数 >1 时再加 0x800（0x1000004 UV 步进）。
     - 形状：盒不加；圆环加 0x20000；球加 0x30000。
   - **粒子标志**：基础值 0x41（标准 + 速度）；颜色 0x04；纹理坐标 0x08；尺寸 0x20；旋转 0x10；多段 0x200；步进 0x800。
   - 用 0x5A2500 / 0x5A2750 建类，再用 0x59CB80 建原子和发射器。发射器属性区先清零，然后调 0x5A02E0 填默认值（seed=1）。
   - 把 payload 写进各属性（§2），把 uvlist 的第 0 帧和最后一帧写进纹理坐标属性的起点和终点。
   - 帧数 >1 时，写 UV 步进表：前 n−1 帧各一项，`time_i = (第 0..i−1 帧时长和) / (第 0..n−2 帧时长和)`，项内存第 i 帧的 (u0,v0)/(u1,v1)。
3. 0x46AB80：
   - 0x4682B0 拷贝发射参数；
   - pos 非空时，0x468410 建 frame 并平移到 *pos；
   - 0x467D40 绑定 uvlist：只加载**第 0 帧对应的那张贴图**，存到 std+0xA4；
   - 0x46ACD0 建 PTank：容量为 max_prt，格式 0x100000A7（位置、颜色、尺寸、2D 旋转、四分量 UV 都按粒子各自存储）；
   - 写 PTank 的混合参数：+0xAC = vertex_alpha，+0xA4 = src_blend，+0xA8 = dst_blend；
   - 设时长：obj[0] = duration，obj[1] = 0。

发射位置偏移 emtPos（std+0x1C）游戏从不设置，恒为 0，所以发射盒以发射器原点为中心。

### 3.2 每帧更新顺序（0x46D470 → 0x46B010 → 0x59CC60 → 0x59D9C0）

对每个效果依次执行下面 7 步：

1. **游戏层计时**（0x46B010）：若 duration > 0.001，则先判断 `elapsed <= duration`：成立时 `elapsed += dt`，否则关闭发射标志（flags &= ~8）。
2. **BEGINUPDATE**（0x5A0570）：
   - `ltm = RwFrameGetLTM(发射器 frame)`；
   - `currTime += dt`。
3. **粒子更新**：对每个粒子批，先把"本帧新粒子起点"标记设为 −1，然后按下面顺序调用粒子回调：
   - 先调 prtadv 的扩展回调：多段颜色 0x5A3F10 → UV 步进 0x5A3780；
   - 最后调标准更新 0x59E4F0；
   - 粒子数为 0 的批放回空闲链表。
4. **发射**（仅当 flags & 8）：依次调
   - 标准发射 0x59F0E0
   - → 形状（球 0x5A2D60 / 圆环 0x5A3220）
   - →（链式 0x5A5B60）
   - → 多段颜色 0x5A4140
   - → UV 步进 0x5A3870

   形状和扩展回调只处理本批**刚发射的粒子**。
5. **ENDUPDATE**（0x5A0630）：若 `emitTime <= currTime`，则
   - `prevEmitTime = currTime`；
   - 推进一次随机数；
   - `emitTime = currTime + emit_gap + r*emit_gap_bias`。
6. 解锁 PTank，粒子数 = 存活数 + 新发射数。
7. **游戏层收尾**（0x46D470）：
   - 若 `duration < elapsed`，关闭发射标志；
   - 若发射已关且粒子数为 0（且该对象可回收），就从活动表移到该 id 的回收池。

发射器初值 currTime = emitTime = 0，所以第一帧就会发射。

### 3.3 标准发射（0x59F0E0）与随机数顺序

条件：`emitTime <= currTime`。

1. 计算本批个数：
   - 抽 1 个随机数 r，`n = emit_num + trunc(f32(r * emit_num_bias))`（FPU 控制字 \|0xC00，向零截断）。
   - 若 `n > max_prt − 当前存活数`，令 n 为差值。
   - **若 n ≤ 0 则直接返回，种子不写回**（相当于这次没有抽过）。
2. 新粒子追加到最后一个批的末尾；放不下时新开一批，批容量为 max_prt。所以总体顺序就是发射顺序，死亡粒子在更新时被稳定地压缩掉。

每个新粒子按下面顺序抽随机数，每次抽取都推进一次 LCG：

| 顺序 | 次数 | 用途 | 公式 |
|---|---|---|---|
| 1 | 1 | 寿命 | `end = life + r*life_bias`，`inv = 1/end`，`cur = 0` |
| 2 | 3 | 方向 x,y,z | `d_i = dir_i + r*dir_bias_i`，`d = normalize(d)`；有 LTM 时 `d = LTM 的 3×3 × d`（含缩放） |
| 3 | 1 | 速率 | `vel = (vel + r*vel_bias) * d` |
| 4 | 3 | 位置 x,y,z | `lp_i = r*emt_size_i`，`pos = LTM × lp`（点变换） |
| 5 | 2+2 | 尺寸（有尺寸属性时） | 起点 `s = size_start + r*size_start_bias`（w,h）；终点 `e = size_end + r*size_end_bias`；`delta = e − s` |
| 6 | 4+4 | 颜色（键 ≥2） | 起点 RGBA = `key0 + r*bias0`；终点 = `key[n−1] + r*bias[n−1]`；`delta = 终 − 起`（float，0..255） |
| 7 | 1+1 | 旋转（有旋转属性时） | `a = rot_start + r*rot_start_bias`，超出 ±π 时折回一次（±2π）；`delta = (rot_end + r*rot_end_bias) − a` |
| 8 | 4+4 | 纹理坐标（simple_mode=0 总有） | 起点 = 第 0 帧 (u0,v0,u1,v1)，终点 = 最后一帧。偏差全为 0，但**照样抽 8 次** |

刚出生的粒子以起点值写入 PTank，当帧就会画出。颜色写入时截断取低 8 位。

**球形发射**（0x5A2D60，效果 14）。对本批新粒子：

- 依次抽 `φ = r*3.1415925`、`z = r`、`q = (int32)seed*2^-32 + 0.5`（注意按有符号数转换，q ∈ [0,1)）。
- `R = sphere_radius + q*sphere_radius_gap`。
- 本地位置 `(R·cosφ·√(1−z²), R·sinφ·√(1−z²), R·z)`，经 LTM 变换后**覆盖**标准发射给出的位置。
- sphere_use_emission==1 时，再抽 1 次并改写速度：`(vel + r*vel_bias) * LTM·normalize(本地位置)`。

**多段颜色**（0x5A4140，键 ≥3）。入口先空推进 1 次随机数（不使用）。然后对每个新粒子（cur==0），设中间键为 m_0..m_{k−1}（k = n−2）：

- 依次抽 `t_j = time_j + r*time_bias_j` 和 4 个颜色 `c_j = rgba_j + r*bias_j`。
- 生成 k 个切换时刻 `T_j = t_j * 寿命`，以及各段的 (start', slope)：
  - 段 j（m_j→m_{j+1}）：`slope = (c_{j+1}−c_j)/(t_{j+1}−t_j)`，`start' = c_j − t_j*slope`；分母 ≤0 时 slope 取 0。
  - 末段（m_{k−1}→终点色）：`slope = (终点色 − c_{k−1})/(1 − t_{k−1})`，终点色 = 标准发射得到的 start+delta。
- 第一段（起点色→m_0）直接改粒子的 delta：`delta = (c_0 − start)/t_0`，start 不变。
- 更新时（0x5A3F10）：若 `idx < k` 且 `T_idx <= cur+dt`，就把 (start', slope) 换成第 idx 段并令 idx++。**每帧最多切一段**。标准更新按 `start + t*delta` 计算，因此得到分段线性的颜色。

**UV 步进**（0x5A3870，帧数 >1）。入口先空推进 1 次随机数。然后对每个新粒子，对 n−1 个步进项依次抽 1 次时刻和 4 次 UV（偏差全为 0），生成切换时刻 `T_i = time_i * 寿命`，并把粒子的 UV delta 清零。

- 更新时（0x5A3780）：若 `idx < n−1` 且 `T_idx <= cur+dt`，UV 起点换成第 idx 帧，idx++。
- 结果是第 i 帧在年龄 ∈ [T_i, T_{i+1}) 时显示，**第 n−1 帧（最后一帧）从不显示**。

### 3.4 标准粒子更新（0x59E4F0）

对每个粒子：

```
if !(cur < end): 丢弃（不复制到压缩后的数组）   // 先判断，再加 dt
t = (cur + dt) * inv ; cur += dt ; if t > 1: t = 1   // 没有下限钳制
vel += dt * force                                  // force 是世界坐标
pos += dt * vel                                    // 用更新后的速度
size  = size_start + t*size_delta                  // 若有尺寸属性
color = trunc(start + t*delta) & 0xFF（每通道）      // 若有颜色属性；先存成 f32 再截断
uv    = uv_start + t*uv_delta                      // UV 步进时 delta=0
rot   = rot_start + t*rot_delta                    // 若有旋转属性
```

几点推论：

- 粒子在 `cur ≥ end` 之后还会再画一帧（这一帧 t 被钳到 1），下一帧才删除。
- 寿命为负的粒子只在出生那一帧画一次。

### 3.5 绘制（Article_RenderEffect 0x46D7F0 → 原子渲染 → PTank 0x593A90 / 0x5940C0）

#### 全局渲染状态

0x46D7F0 先保存当前状态，然后设置：

- ZTESTENABLE=1，ZWRITEENABLE=0；
- CULLMODE=2（rwCULLMODECULLBACK）；
- SRCBLEND = DESTBLEND = 2（ONE）。

所有效果画完后恢复原状态。用到的 RwRenderState 编号与 RW 3.7 一致：6 ZTEST、8 ZWRITE、10 SRCBLEND、11 DESTBLEND、12 VERTEXALPHA、20 CULLMODE、29 ALPHATESTFUNCTION、30 ALPHATESTREF。

#### 绘制时机

在场景 3D 绘制（0x4A1A80，原名 OnLostFocus，实为渲染）中，粒子的位置如下：

1. 地图与摆件（此时 alpha 测试为 GREATEREQUAL 196），之后把 alpha 测试改为 ALWAYS(8)、VERTEXALPHA 改为 1；
2. 骰子；
3. **粒子**；
4. 角色和光照几何。

另外，粒子也会被画进水面反射（0x478340）。

#### PTank 的状态（0x5940C0）

- **光照**：关闭。
- **纹理阶段 0**：COLOROP = MODULATE(TEXTURE, DIFFUSE)，ALPHAOP = MODULATE(TEXTURE, DIFFUSE)。没有逐粒子颜色时，第二参数改用 TFACTOR（常量色）。
- **混合**：若 vertex_alpha ≠ 0，就设 SRCBLEND=src_blend、DESTBLEND=dst_blend、VERTEXALPHAENABLE=1（RW 会据此打开 ALPHABLENDENABLE）。全部 26 个效果都走这条路径。
- **纹理过滤**：线性（0x46ACD0 写 raster filter=2）。
- **雾**：不改动，沿用场景当前的雾状态。

#### 广告牌几何（0x593D60 + 0x5953F0 + 0x596180）

1. 取相机 frame 的 LTM，令 `X = −cam.right`、`Y = cam.up`。RW 相机的 right 指向屏幕左，所以 X 就是屏幕右，Y 是屏幕上。
2. 对每个粒子，设 c=cos(rot)、s=sin(rot)：
   - `A = (c·X − s·Y) · w/2`
   - `B = (c·Y + s·X) · h/2`
   - rot>0 时四边形在屏幕上顺时针转。
3. 四个顶点：

   | 顶点 | 位置 | UV |
   |---|---|---|
   | v0 | P−A−B | (u0, v1) |
   | v1 | P+A−B | (u1, v1) |
   | v2 | P+A+B | (u1, v0) |
   | v3 | P−A+B | (u0, v0) |

   其中 (u0,v0) 是帧格子的左上角，(u1,v1) 是右下角，所以贴图按正常方向显示。
4. 索引为 (0,1,2)、(0,2,3)。顶点色就是 PTank 中的颜色（4 个顶点相同）。

移植时，正面朝向或背面剔除方向不容易保证与原版一致，建议**画粒子时直接关闭剔除**。

#### 混合枚举

rwBLEND 的数值与 D3DBLEND 相同：1 ZERO、2 ONE、3 SRCCOLOR、4 INVSRCCOLOR、5 SRCALPHA、6 INVSRCALPHA、7 DESTALPHA、8 INVDESTALPHA、9 DESTCOLOR、10 INVDESTCOLOR。

### 3.6 时间与随机数细节

- **dt**：主循环 0x4035E0 计算 `dt = min(Δms*0.001, 0.1)` 秒，经 0x403700 → 场景 vf1（游戏场景是 0x4A17B0）传到 `Article_UpdateEffect(dt)`。
- **地图加载**：0x4A33D0 在加载末尾调一次 `Article_UpdateEffect(1.0)`，0x50C930 也会这样调。效果是首帧前先发射一批，并把下次发射时间推到 1.0+gap。
- **LCG 换算**：随机值 r 由 `fild`（把 u32 当 64 位整数）× 2^-32 × 2 − 1 得到，在 x87 上计算。各量写回时按 f32 舍入，模拟器在相同位置做了 f32 舍入。
- **近似算法**：RwV3dNormalize 和 sqrt 用查表近似（约 12 位尾数），模拟器改用精确值，误差约 1e-4 量级。
- **多发射器**：每个发射器有独立的种子（都从 1 开始）。所以两个相同效果的摆件，粒子序列完全一样，只是位置不同。

### 4.2 挂点号的含义与位置跟随

#### 挂点号来自 frame 用户数据

- 父摆件的 role.bin 第 1 个子表（12 字节项 `{hook, child_art, -1}`，即记录体 +0x690/+0x694 向量）在 0x455BD0 末段处理。
- 0x45DDA0 / 0x45DD40 遍历父 clump 的**所有 atomic**，读 0x461CB0 返回的 atomic 插件标志（插件 0x1FF）。标志低 4 位非 0 的，记录 `{标志, RwFrameGetLTM(atomic 的 frame)}`。
- 这个标志在加载时由 0x45C370 解析 **frame 用户数据**（RpUserData，字符串）得到，串的形式是 `[...]`：
  - `@` 后的一位十六进制数作为低 4 位；
  - `#` `$` `%` `^` `&` `*` `(` `)` `z` `w` 分别置高位标志。
- 匹配条件是 `标志 == hook`，按整个 32 位比较。所以挂点 frame 的串里只能有 `[@n]`，不能再带其他标志字符。

**例**：BG03.dff（魔法屋，art 603）的第 2 个 frame，用户数据为 `"[@1]Plane01"`，父 frame 是根下的 frame 1。它在模型空间中位于 (−7.26, 68.47, −0.54)，旋转为单位阵，即锅口。其余例子见 `out/prt_review/hook_frames.txt`。

**结论**：挂点号与 HAnim 节点号无关，指的是"用户数据串为 `[@n]…` 的那个 atomic 的 frame"。

#### 位置跟随

1. 加载时：0x455BD0 用 SpawnEffect(eff, &(0,0,0)) 建发射器（frame 位于原点），然后立即 0x46CBF0 Article_CopyMatrix(effect, 挂点 LTM 指针)。
2. 之后每帧：父摆件的 Article_Update（0x448540，遍历 +0x42C 子表）都会再次 CopyMatrix：把挂点 frame 的 LTM（16 个 float）整个拷进发射器 frame 的 modelling matrix，并标记 dirty。
3. BEGINUPDATE 再取这个 frame 的 LTM。

所以发射器矩阵 = 挂点 frame 当前的世界矩阵，包括父摆件的摆放位置、模型动画和缩放。注意它读的是 LTM 指针里的缓存值，可能比当帧晚一帧，影响很小。

#### 直接放在地图上的粒子 art

例如 03.map 上的 6102 shine。0x43C470 中 `+0x68==1` 的分支调用 0x46CD00 → 0x468410：新建 frame，只平移到地图记录的位置，不带旋转。

#### LTM 对各物理量的作用

| 物理量 | 是否经过 LTM |
|---|---|
| 发射盒（emt_size） | 经过，包括旋转和缩放 |
| 初速度方向 | 经过 3×3 部分，含缩放，所以速率也随缩放变化 |
| 力（force） | 不经过，直接按世界坐标 |
| 粒子尺寸 | 不经过，按世界单位 |

## 7. 移植实现注意事项

1. **按 §3.2 的固定顺序更新。** 顺序是：游戏计时 → currTime+=dt → 粒子更新（扩展回调在前，标准更新在后）→ 发射 → 安排下次发射。
   - 新粒子当帧不积分，但要画出来。
   - 死亡判断在加 dt 之前，所以粒子会比寿命多画一帧。
2. **max_prt 截断是外观的关键。** 许多效果的发射速率远大于 max_prt/寿命，例如效果 2、3、4 每帧发 200 或 20 个，上限却只有 10。实际效果是"死一个补一个"。如果不截断，效果会完全不同。
3. **随机数用逐粒子的 LCG。** 即使不追求逐位一致，也应该用"基值 + 均匀(−1,1)×偏差"的形式。
   - 方向是先加偏差再归一化，不要按角度随机。
   - 发射个数按截断计算。
4. **UV 动画的规则：**
   - 按寿命比例步进，不按毫秒；
   - 只用前 n−1 帧；
   - 整个效果只用第 0 帧那张贴图；
   - UV 不插值。
5. **坐标空间：**
   - 粒子位置在发射时就进入世界坐标，之后不受发射器移动影响；
   - 力（force）是世界坐标；
   - 方向和发射盒要经过挂点矩阵变换，包括缩放。
6. **绘制状态：**
   - 广告牌朝向用相机的屏幕右轴和屏幕上轴，不是"朝向相机位置"的球形广告牌；
   - 尺寸是整宽；
   - 屏幕内旋转方向见 §3.5；
   - 关深度写入、开深度测试，建议关闭剔除；
   - 混合因子按表映射到 GL：ONE→GL_ONE，SRCALPHA→GL_SRC_ALPHA，INVSRCALPHA→GL_ONE_MINUS_SRC_ALPHA，SRCCOLOR→GL_SRC_COLOR，INVSRCCOLOR→GL_ONE_MINUS_SRC_COLOR；
   - 颜色是 `tex × vcolor`。
7. **绘制时机：** 在地图摆件和骰子之后、角色之前，粒子之间按发射顺序绘制。原版不对粒子排序，也不写深度，所以后画的角色会盖住它们。
8. **挂点要读 DFF frame 的 RpUserData 字符串**（librw 的 userdata 插件），按 `[@n]` 找到 frame，每帧取它的世界矩阵。
9. **地图加载时可以选做一次 dt=1.0 的预热**（与原版一致）。

## 8. 未知 / 未覆盖

- payload 中 0x06（u16）和 0x74（u32）没有找到读取代码，数据中全为 0。
- 圆环（shape=1）、链式子发射器（chain_effect）和 simple_mode=1 的代码已定位，字段名来自代码，但数据中没有用到。模拟器没有实现，遇到会报 NotImplementedError。
- kind=1（0xD8 字节 payload，0x46B370 等）没有分析，本文件中不出现。
- 回收池复用的发射器会沿用上一次的 RW 状态，包括种子和残留粒子，模拟器只模拟新建的情况。
- 地图加载时那次 dt=1.0 预热时，父摆件的 Article_Update 是否已经执行过 CopyMatrix，即第一批粒子是否发在挂点上，没有核实。
- role.bin 第 4 子表中粒子事件的其他字段（触发时刻、挂接 frame）没有展开。
- 精度差异来自三处：RW 的查表 sqrt 和 1/sqrt；x87 中间精度（D3D9 默认把 FPU 设为单精度）；模拟器只在关键位置做了 f32 舍入。对拍时位置和颜色应允许约 1e-3 的相对误差，颜色字节允许 ±1。

- 先速度后位置的积分顺序与死亡判定；
- 两个扩展回调入口处的空推进；
- 下次发射时间公式；
- 广告牌顶点和 UV；
