## 1. 架构选择

**选定：主机中转的确定性锁步（lockstep），只同步“人类的决定”（命令），所有设备各自跑完整模拟；固定步长；周期性状态哈希；不同步时用主机的逐字节存档快照重新同步。** [N]

```
 客户端 A ──CMD──┐                         ┌──FRAMES(帧号, 命令)──> 客户端 A
 客户端 B ──CMD──┼──> 主机：决定每条命令在哪一帧生效 ──┤
 主机本地输入 ───┘     （主机自己也按同一顺序在该帧执行）  └──FRAMES──> 客户端 B
 每个设备：第 f 帧开始先执行第 f 帧的命令，再跑 1/60 秒的模拟；回合开始 / 每天结束时算存档哈希，客户端报给主机比对
```

理由：
* **大富翁是回合制，玩家决定很少、很稀疏**（一回合几次点击），而模拟状态很大（地块、股票、NPC、Python 随机数、动画计时……）。只传决定，带宽极小（实测 20 天约 150 条命令），手机 + 4G / FRP 转发都没压力。
* **规则用原版 Python 脚本跑**（`python.cpp`），状态散在 C++ 各模块和 Python 解释器里，做“主机算、客户端只显示”的状态流需要把每一帧的可见状态序列化，工作量和带宽都大；锁步则复用全部现有代码。
* **存档已经逐字节可往返**（`save_port.md` 第 9–10 节：读档后继续玩的每天 / 每回合 / 每次掷骰记录与不读档的完全相同），这正好是锁步最缺的两样东西：**状态哈希**（`rm8SaveBuild` 的字节）和**重新同步**（把主机的快照“读档”进来）。
* **主机中转 + 主机定帧**：没有 NAT 打洞（用户要求：局域网或 Sakura FRP 之类映射的 TCP 端口），所有客户端只连主机；主机不等客户端（客户端落后就加速追帧），所以慢设备只影响自己。
* 否决的方案：逐帧输入锁步（所有人每帧互等，手机卡一下全体卡）；P2P 网状连接（需要打洞）；主机权威 + 状态流（见上）；回滚网络（回合制不需要，且 Python 状态难以回滚——快照重新同步已覆盖异常情况）。

延迟体验：远程玩家点一下要经过 主机 → 广播 → 本机到达那一帧 才生效（局域网约 30–80 ms，FRP 视线路而定）；回合制可以接受。主机自己的点击在下一帧生效。

## 2. 确定性风险与处理（PC x86-64 ↔ Android arm64）

| 风险 | 处理 | 状态 |
|---|---|---|
| **浮点乘加合并（FMA contraction）**：clang 对 C/C++ 默认 `-ffp-contract=on`，arm64 上会把 `a*b+c` 编成一条 `fmadd`（只舍入一次），x86-64 基线没有 FMA 指令（不会合并）→ 同一表达式结果末位不同 | `CMakeLists.txt` 全局 `add_compile_options(-ffp-contract=off)`（app、librw、CPython 2.4、SDL2 全部）。**实测**：`libmain.so` 里融合乘加指令 `fmadd/fmsub/fnmadd/fnmsub` 1784 条 + 向量 `fmla/fmls` 229 条 → **0**；PC 版 `vfmadd*` 前后都是 0（PC 代码不变，见第 8.3 节单机逐字节对照） | 已处理 [N] |
| `-ffast-math` 等 | 没有任何目标用 fast-math（`CMakeCache` 只有 `-O3 -DNDEBUG`） | 已核对 |
| **char 有无符号**：arm64 默认 `char` 无符号，x86 有符号 | Android 加 `-fsigned-char`，与 PC 一致 | 已处理 [N] |
| **libm 超越函数**（sinf/cosf/atan2f/acosf…）：MSVC UCRT 与 bionic 实现不同，末位可能不同 | 模拟里用到的位置全部核对：① 规则用的“相机”改成**联机模拟相机**，由精确常数（sin/cos 225°、40° 的十进制常数，编译器舍入相同）构造，不调 libm（`rm8NetPlaceSimCamera`）；② 角色朝向用的相机偏航 `CAM_YAW` 原来是 `atan2f(...)`，之后 `(int)CAM_YAW` **截断**——末位差一点就会差一个扇区 → 联机固定为精确的 135.0（`rm8RolesFixCameraYaw`）；③ 卡片射程的默认视角在联机时用同样的常数（`cards.cpp` `g_netRange`）；④ `calcAngle` 的 `acosf` 结果取整到整度，道路方向都是轴向 / 对角，不会落在 0.5 度边界；⑤ 骰子飞行方向、NPC / 特效朝向只影响画面，不进存档；⑥ AI 脚本只有四则运算和比较（`out/pysrc_clean` 检索无 math / `**`） | 已处理，④ 为残余风险（理论上） |
| **可变 dt**：交互模式按真实帧时间推进（0.1 s 上限） | 联机时模拟固定 1/60 秒一步（`RM8_NET_STEP`），由 `rm8NetStepsDue` 按真实时间决定每次循环跑几步；客户端不超过主机已确认的帧 | 已处理 [N] |
| **画面 / 相机参与规则**：同格错开的方向向量、角色朝向、骰子方向、卡片射程（`rm8CardsPosInView`）原来都取自玩家正在看的相机（可平移、旋转、缩放），宽高比各设备不同 | 联机时 `rm8RolesSetCamera` 传入**独立的模拟相机**（默认视角、默认缩放，对准回合焦点），玩家的视图相机照常自由移动；卡片射程固定按 **1024×768（4:3）** 计算（人类和电脑相同，等于原版） | 已处理 [N]。代价：联机时玩家转动视角后纸片人仍朝向默认视角（画面小瑕疵） |
| **界面驱动的状态**：悬停（`rm8UiHot`）会改变事件对话框的说明、语音（进而影响等待）；卡片栏长按 1.4 s（墙钟）打开卡片菜单；控件的 enabled / 显示状态部分在**画面帧**里刷新（帧率不同） | 悬停作为命令同步（只同步正在做决定的玩家，`RM8C_UI_HOVER`），模拟界面的 `rm8UiHot` 读同步的悬停；长按 / 右键打开菜单作为命令（`RM8C_CARD`）；同步点击执行时**不检查** enabled / 显示（由处理函数自己按游戏状态判断） | 已处理 [N] |
| **控件 ID**：运行时控件（`rm8UiAddWidget`）的 ID 来自全局计数器，菜单等本地界面也在用，各设备不同 | 命令里用“控件键”：.ui 控件 = 列表下标，运行时控件 = 该界面运行时控件的创建序号（`rm8UiNetKey`） | 已处理 [N] |
| **std::sort 稳定性 / 等值元素顺序**（llvm-mingw 与 NDK 的 libc++ 版本不同） | 模拟代码里的 sort：`rules_plus.cpp:166`（有 tie-break）；其余（boardfx 点击、ui 层叠、scene 材质、存档目录）都不进模拟 | 已核对 |
| **unordered_map 遍历顺序** | 只在 audio / lmpipe / scene / zh（缓存、渲染）里；模拟用 `std::map` | 已核对 |
| **time() / SDL_GetTicks 播种** | 开局种子、Python random 种子、开始日期（星期几由系统日期决定，`game.cpp`）都由主机在 `START` 里给出（`rm8NetSeed`、`rm8SavePySeed`、`rm8NetStartDate`）；读快照不重新播种（`rm8_app.cpp loadSaved`） | 已处理 [N] |
| **C 运行库 rand()**：MSVC 与 bionic 序列不同 | 模拟只用自己的 MSVC 线性同余流（roles / dice / game / stock / boardfx 各一个，都进存档）；`hud.cpp goRollFaces` 的 `rand()` 只换骰子图标（画面）；`story.cpp` 的 `rand()` 只在故事模式（不联机） | 已核对 |
| **Python random**：状态在存档里是有符号 / 无符号 C long 之分（Windows 32 位、Android 64 位） | PYRN 块写的是 `unsigned` 掩码，读时按 `sizeof(long)` 还原（`save_python.inc`），两边字节相同；`random()` 是 53 位整数运算 → double，精确 | 已核对 |
| **Python int 位宽**：Windows `long` 32 位，Android 64 位 | Python 2.4 的 int 溢出会自动变 long，数值相同；脚本不用 `hash()`、不遍历 dict（检索 `AI_*.py` / `CardPy_*.py`） | 已核对 |
| **C++ `long` 位宽**（Windows 32 / Android 64）：溢出时结果不同 | N2：规则 / 状态代码（game、balance、cards、event_*、news、stock、roles、rules_plus、story、python.cpp、save_*.inc 等 30 个文件）里的 `long` 全部改成 `int32_t`（Windows 上〔sp_NN.bin#spl_16〕 32 位，行为逐位不变）；会溢出的金额 / 点券运算改用 `turn.h` 的 `rm8Add32 / rm8Sub32 / rm8Mul32`（经 `uint32_t` 回绕，等于原版 x86 的 add / imul 截断），浮点转整数用 `rm8F2I32`（越界 / NaN 得 0x80000000，同 x86 cvttsd2si；arm64 原来会饱和）。**发现的 3 处原来就两平台不同**：利息新闻（存款 × 10 / 100，存款 > 214748364 时）、存款百分比新闻、进阶规则 AI 的“现金 × 3”比较。Python 接口（`PyInt_AsLong` 等 C long）只在边界保留 `long`，进入游戏状态前经 `pyI32 / pyIsInt32` 按 32 位 long 的语义转换（超范围 = Windows 上的 OverflowError / PyLong）；`"l"` 参数显式转 `(long)`；`rm8SavePySeed` 用 `(long)(int32_t)seed` | 已处理 [N] |
| **等语音播完**（“waits for the voice to finish”）：事件对话框、角色等待（`rm8PresentSeatFxBusy`）、月结算都等 `rm8SndPlaying`；实际播放受设备、缓冲、无声卡、后台影响 | 联机时 `audio.cpp` 打开**确定性采样时钟**：`rm8SndPlay` 总返回句柄，时长 = WAV 头里的 PCM 长度 × 次数，由 `rm8AudioDetTick(1/60)` 倒数；`rm8SndPlaying` 只看这个时钟。声音照常播放。没有声卡的设备也一样 | 已处理 [N] |
| **点击跳过**（`skip.md`）：本地一点就缩短等待 | 只有正在做决定的玩家的跳过会作为命令（`RM8C_SKIP`）在同一帧生效；别人点了不跳 | 已处理 [N] |
| **'.' 加速**（`rm8GameSpeed`）与选项里的速度 / 难度 / 进阶规则 | 速度、难度、进阶规则开关取主机的（`START`）；局内改选项不影响联机局（`menu.cpp applyOptions`、`rm8Difficulty`、`rules_plus.cpp`）；'.' 只有主机能按，作为命令 | 已处理 [N] |
| **托管键 / 任意键放回**（`autoplay.md`） | F1..F4 / 点头像只对自己的座位，作为命令；`rm8AutoRelease`（任意键放回别人的托管座位）联机时不用 | 已处理 [N] |
| **小游戏**：在一台设备上实时操作，结果改变规则状态 | N4（第 7 节）：小游戏画面、输入、音效（`rm8SndPlayLocal`：小游戏自己的句柄段，不进确定性采样时钟）、随机数（`mg::rand15`，种子取自规则随机流在落地那一帧的一个值，每台设备相同）都只在本机；进模拟的只有**结果命令**（单人小游戏）或**裁判的动作命令**（插海盗），所有设备在同一帧执行。小游戏不碰规则随机流、骰子流、Python random、进阶规则随机流（裁判有自己的 MSVC 线性同余状态） | 已处理 [N] |
| 未初始化内存、浮点转整数越界（x86 得 INT_MIN、arm 饱和）、整数除零 | 无已知实例；由哈希兜底 | 残余风险 |

**兜底**：上面任何一项漏网都会让哈希不一致 → 主机自动重新同步（第 4.5 节），表现为客户端短暂停顿后继续。

**谁能下命令**（主机在排入帧时最终判定，`permitted`）：命令要作用于“游戏正在等谁”——`rm8NetInputSeat()`：处于状态 7 的座位（`Role_OpenModalUi` 的对话框、卡片选目标），否则手牌满换牌的座位（`rm8CardsSwapSeat`），否则正在运行的事件对话框的 `inputSeat()`（拍卖 = 当前出价者，`event_vendue.cpp`），否则当前座位。该座位必须是人类（非电脑、非托管），且属于发命令的玩家；**主机可以代断线玩家操作**（否则对话框会卡住）。托管键只对自己的座位；`AUTOSET` / `FAST` / `SEAT` / `ADOPT` 只主机。续玩的“等待玩家中…”期间（帧 0 不走）所有命令都不接受。观战者（没有座位的客户端）的命令永远不被允许。[N4] 小游戏等结果时（`rm8EventMiniWaiting`）棋盘上的命令一律不接受，只接受上表的 `MINI_RESULT` / `MINI_ACT`（主机排帧时按裁判当时的状态检查第几剑、轮到谁；过期的动作在执行时被所有设备同样忽略）。小游戏自己的界面（`lg__*` 说明框等）是本地界面，点击不变成命令。

## 4. 协议

### 4.1 传输
* TCP（主机监听一个端口，默认 **47000**，`rm8_settings.txt` 的 `net_port`；局域网直连，外网用 Sakura FRP 等把这个 TCP 端口映射出去，客户端填映射后的 `域名:端口`）。IPv6 双栈监听（IPv4 客户端照样连）。
* 非阻塞套接字，主循环每帧轮询（`rm8NetPoll`，菜单里、后台暂停时也调用）；只有“解析域名 + 连接”在一个短线程里（`getaddrinfo` 会阻塞），8 秒超时。`TCP_NODELAY`。
* 帧格式：`u32 长度 | u8 类型 | 载荷`，小端（x86 与 arm64 都是小端，载荷用 `save.h` 的 `Rm8SaveW / Rm8SaveR`）。单条上限 8 MiB（快照约 30 KB）。

### 4.2 消息

| 类型 | 方向 | 内容 |
|---|---|---|
| HELLO | 客→主 | 魔数 `RM8NET01`、协议版本（N2 = 2，N4 = **3**：客户端的小游戏命令；先比对，不同时给出“主机 x / 你的程序 y”）、**构建哈希**（N2 起以字符串发送，拒绝信息里给出双方的值）（`cmake/netbuild.cmake`：全部 app 源码 + CMakeLists 的 SHA-256 前 16 位，PC 与安卓同一份源码得到同一值，实测两边相同，例如 `df6fd648f0aea310`）、**数据哈希**（`scenes/` 下所有 txt、`game/Pysrc`、`game/Config`、音效包索引，FNV-1a 64；同一份 rm8_extract 输出相同）、会话 id + 重连令牌（没有则 0；`net_session.txt`）、名字、设备玩家 id（`net_id.txt`） |
| WELCOME / REJECT | 主→客 | 分配的 peer id、会话 id、令牌 / 拒绝原因（中文，客户端直接显示：协议版本不同、程序版本不同（双方构建号）、数据不同（双方数据校验）、房间已满（最多 7 位客人，玩家和观战都算）、主机还没打开房间、握手超时 / 数据损坏）。连接失败本身也分开提示：**连接被拒绝**（那个地址上没有主机在等）、**连接超时**（地址不对 / 防火墙 / FRP 没开）、找不到主机名 |
| LOBBY | 主→客 | [N2] 主机菜单的镜像：当前画面（1 地图菜单 / 2 角色菜单）、选中的座位、地图、五个开局选项、每个座位（角色、服装、是否电脑、类型：主机本机 / 等待网络玩家 / 电脑、座位序号、坐在上面的 peer、准备、在线、名字），以及房间里所有在线的人（含观战）。有变化就发，否则 3 秒一次 |
| READY | 客→主 | 准备 / 取消（镜像菜单里按 O） |
| PICK | 客→主 | [N2] 客户端要求自己座位的角色 / 服装（主机检查“同角色同服装只能一个”，`rm8MenuNetSetSeatRole`） |
| ROOM | 主→客 | [N2] 续玩的“等待玩家中…”面板：是否还在等待、每个座位（角色、状态：本机 / 等原玩家 / 空位 / 电脑 / 开放给玩家的电脑座位、玩家、玩家 id、名字、是否已回来）。帧 0 静止时客户端用它更新座位表 |
| START | 主→全体 | 会话 id、**种子**、**开始日期**（年月日星期）、速度 / 难度 / 进阶规则、setup（地图、资金、点券、交通工具、时限、胜利条件、座位 + 是否电脑）、每座位的玩家（peer、名字、玩家 id）——**是接收方起点（开局 / 快照）那一刻的座位表**；模式 0 = 现在建新棋盘，1 = 后面跟 BASE（重连、观战、续玩） |
| LOADED | 客→主 | 棋盘已建好 / 快照已载入（主机开局时等所有人 LOADED，最多 20 秒） |
| FRAMES | 主→客 | 已确认到的帧号 + 这一批命令（帧号、类型、发起者、参数）；约 30 次 / 秒，有命令立即发 |
| CMD | 客→主 | 一条本地决定（主机校验类型、字符串、发起者，再排入下一帧） |
| HASH | 客→主 | 帧号、类别（0 天结束 / 2 回合开始）、存档哈希 |
| BASE | 主→客 | 重新同步的起点：主机最近一次“天结束”的快照（帧号 + 存档字节），或者“从开局重建”（还没有快照时）；随后一条 FRAMES 带上这之后的全部命令。续玩时帧 0 的快照就是读入的存档本身 |

### 4.3 锁步与帧
* 主机：每次主循环按真实时间累计，满 1/60 秒跑一帧（最多 8 帧 / 次；设备慢时游戏变慢而不是爆发追赶）；第 f 帧开始时把待处理命令按到达顺序校验、编上帧号 f、执行、写入日志与发送批次。
* 客户端：只跑到主机确认过的帧；落后超过 6 帧时每次多跑一些（最多 16 帧 / 次，落后 600 帧以上时 90 帧 / 次）追上。
* 每一帧（`rm8_app.cpp`）：放置模拟相机 → `rm8RolesSetCamera(模拟相机)` → 默认射程视角 → 执行本帧命令 → `rm8UpdateScene` → `rm8RolesUpdate` → `rm8EventUpdate` → `rm8StoryUpdate` → `rm8AudioDetTick` → 帧号 +1 → `rm8StoryDispatch`（游戏结束）。

### 4.4 哈希
* `save.cpp rm8SaveBoundary` 每次调用先进 `rm8SaveHooks().netBoundary`：回合开始（类别 2）和天结束（类别 0）时 `rm8SaveBuild(时间清零)`，FNV-1a 64。客户端报给主机，主机比对自己同一帧同一类别的值（保存最近 4096 个）。
* 天结束的那份同时是主机的**快照**（`save_port.md` 第 9 节验证过的读档点：存档写在回合循环中间，读档补完那一帧的尾巴），主机清掉快照之前的命令日志。

### 4.5 重新同步、重连
* 哈希不一致 → 主机给该客户端发 `START` + `BASE`（最近的快照）+ 快照之后的全部命令；客户端把快照字节写成 `net_snapshot.sav`，走正常的读档路径（`loadSaved`，联机时不重新播种，规则相机用模拟相机）重建棋盘，帧号设为快照帧，再按命令追到现在。主机不暂停，其他客户端不受影响。
* 断线：客户端每 3 秒重试，最多 90 秒，状态行显示“与主机的连接中断，正在重连…”；主机立刻用 `AUTOSET` 把该玩家的座位交给电脑（状态行“xx 已断线”），正在等他做的对话框由主机代为操作。重新连上（`HELLO` 带会话 id + 令牌，**app 重启后也行**：令牌存在 `net_session.txt`）→ 同上的 BASE + 命令 → 载入后主机发 `AUTOSET` 关，把座位还给玩家。
* [N2] 回来的玩家先按重连令牌认，再按**设备玩家 id**（`net_id.txt`，app 重装 / 换数据目录才会变）认，局内再按**名字**认（换了设备的玩家）；认出来就是原来的 peer，原来的座位。中途交还座位只在**回合边界**做：该座位不是当前回合、游戏也没在等它做决定时（`safeSeat`），主机才发 `AUTOSET` 关 / `SEAT`。
* 安卓切到后台：`SDL_HINT_ANDROID_BLOCK_ON_PAUSE=0`，主循环在后台继续跑（不画、不跑模拟，只轮询套接字、回心跳），所以短时间切走不会断线；回到前台时 `rm8NetAppPaused(false)` 给所有连接一个宽限（重置收包计时），客户端随后快速追帧。主机切到后台时模拟暂停，客户端状态行显示“主机暂时没有响应（可能切到了后台），请稍候…”。真的断了（系统杀掉网络 / 超过 20 秒）就走上面的重连（90 秒内）。
* 主机退出：发 `BYE`，客户端回到联机页并显示原因。

### 4.6 安全
* 长度上限、计数上限（座位 ≤ 4、命令批 ≤ 100000、字符串 ≤ 200）、界面名只允许字母数字下划线、命令类型白名单、主机专用命令不接受来自客户端、握手前只接受 HELLO / PING（10 秒超时）。
* 远程数据只会被解释为：命令（固定的处理函数）、存档快照（`rm8SaveParse` 先完整校验结构再应用）、显示文本。**不执行任何远程代码，不按远程数据打开文件路径。**
* 没有加密 / 认证（局域网 / 朋友间使用；FRP 公网映射时任何知道地址的人都能尝试连接，但只能占空座位）。

  * 角色菜单的 O（开始）不直接开局，先检查准备：全准备 → 开始；否则弹出原版风格的确认框 **「玩家准备不全，是否强制开启？（没准备好的座位由电脑接管）」**（`popo` 对话框框 + 原版的确认 / 取消图片，键盘 O = 确认、Esc = 取消）。强制开始时没准备 / 空着的等待座位变成电脑。

  * **O = 准备 / 取消准备**，**X / Esc = 离开房间**；
  * 在角色菜单点右边的角色头像 / 服装按钮 = **请求换自己座位的角色 / 服装**（主机检查同角色同服装只能有一个，`PICK` 消息）；点别的座位只是查看。

## 6. 存档与续玩

* 联机局里只有**主机**能存档（gsys 存档；客户端点了提示“只有主机可以存档”），也只有主机写自动存档（客户端 `rm8SaveHooks().noAutoSave`）。局内读档禁用。存档就是普通的自由模式槽 `record_mNN.sav`。
* 扩展块 **`NETP`**（order 60，`net.cpp`）：每个座位**现在**的玩家（peer、设备玩家 id、名字；`RM8C_SEAT` 换人时同一帧在所有设备上改）。**只在联机局里写**，单机存档没有这一块（逐字节不变）；每台设备写出相同字节，所以它也在哈希里。
* **续玩**（主机：联机对战 → 读取联机存档 → 原版的读档菜单选一个自由模式存档；`rm8NetHostResume`）：
  1. 开始监听，**本机读档**（与单机读档同一路径，联机时不重新播种，规则相机用模拟相机），这一刻就是联机局的**帧 0**；模拟停在这里（`waitPlayers`），显示“等待玩家中…”面板。读档前先从文件里扫出 `NETP`（`scanNetp`）把座位表定好，所以读档时自己的天结束边界、自动存档写的 `NETP` 都已正确。
  2. 座位分配：存档的人类座位（含托管中的）——`NETP` 里的玩家 id = 本机 → 主机本机；其它 id → **等原玩家**（建一个离线的 peer 记录，名字来自存档）；没有 id → 空座位。电脑座位保持电脑，主机可以点“开放给玩家”。
  3. 客户端照常“加入游戏”。主机按重连令牌 / **玩家 id** / 名字认出原玩家 → 发 START（模式 1）+ BASE（帧 0 = 这份存档）→ 客户端载入，面板显示“已回来”。空座位 / 开放的电脑座位给新来的人；**没有座位的新来者 = 观战**（照常同步，命令不被接受）。
  4. 主机按「开始游戏」（或者等全部回来）：第 1 帧起游戏继续。没回来的人类座位、没人坐的空座位 → `AUTOSET` 开（电脑托管）；开放的电脑座位 → `ADOPT`（变成“玩家座位、电脑托管”），有人坐了就立刻 `AUTOSET` 关。
  5. 开始以后才回来的原玩家：认出 → BASE（最近的天结束快照 + 之后的命令）→ 载入后在**回合边界**（不是该座位的回合、游戏没在等它）`AUTOSET` 关，座位交还。新玩家坐进还空着的座位：同样在回合边界发 `RM8C_SEAT`（座位表 + `NETP` 改）再 `AUTOSET` 关。
* **单机存档拿来联机**（决定）：同样走“读取联机存档”。存档没有 `NETP` → 第一个人类座位归主机本机，其余人类座位（热座的另一个人）变成**空座位**，给加入的人；电脑座位默认保持电脑，主机可以逐个“开放给玩家”（`ADOPT`）。想自己一个人继续就不要用联机——在单机菜单读同一个档即可（联机读档不改文件，存档始终是普通的自由模式存档）。
* 联机存档在单机里读：`NETP` 块被识别但不用，按 setup 里的人类座位变成本机的人类座位（热座），托管中的座位保持托管（原版 +0x1B0 = 2）。
* **规则保持原版**：自由模式没有接关；电脑都破产、只剩人类时**不问“是否继续”**（`game.cpp` 破产判定：没有玩家座位了 → 0x74 回地图菜单；只剩一个玩家座位 → 0x75 胜利；否则继续结算，原版自由模式就是这样，[V] `AskContinueNextRound @0x48f8e0` 自由模式直接置状态 3）。托管中的座位、开放给玩家的电脑座位都算“玩家座位”（原版 +0x1B0 != 1 的计数），所以把电脑座位开放给玩家会让它参与这个计数——这是把它变成玩家座位的本义。游戏结束时所有设备同一帧结束，联机会话随之关闭。

## 7. 小游戏（N4，2026-11-19）

N1 的临时做法（联机时事件 0x12..0x17 一律电脑代玩）已删除：`events.cpp createTask` 对 0x12..0x17 总是建 `makeMiniTask`，电脑座位照旧在落地处走 `aiMiniGame`（[V] `MiniGame_ExecuteGame @0x4fcb10`），只有 0x15 在有人类时进任务（原版也如此）。

**哪些是“所有人一起玩”的游戏**（核对 `docs/minigames/*.md`）：只有**插海盗 21**（lg_21.md：2~4 人轮流插剑，海盗随机选一人）。18 快手小厨师、20 打地鼠、23 踩蛋在原版里有“第二名人类当扰乱者”的模式，但那是**同一台电脑、同一个键盘**的实时双人（lg_18 §1 模式 2、lg_20 “2P 〔string.bin#6974〕”、lg_23 模式 2），奖励只发给当前玩家；19 挖宝、22 分裂球只有一个人。联机时这五个都按**单人小游戏**处理（第二个人的扰乱者位置由该游戏自己的 AI / 空着，同原版没有第二个人类时一样）——跨设备实时同步一个动作游戏不在本阶段范围内（决定，见第 9.3 节）。

### 7.1 单人小游戏（18 / 19 / 20 / 22 / 23）
* 落地那一帧，每台设备都建同一个任务（`event_mini.cpp MiniTask`），从规则随机流取一个数当小游戏种子（单机同样取，规则流保持一致），然后**模拟停在任务里**（回合不前进，`mayDecide` 不接受棋盘命令）。
* **只有行动座位的主人的设备**跑小游戏（全屏、本地输入、本地音效与随机数；`rm8NetMiniMayStart`：重连 / 追帧中的设备不开）。其他设备在棋盘上显示原版 `popo` 框风格的等待面板（`net_ui.cpp netmini`：角色头像、「小游戏「打地鼠」」、“大老千（Bob） 正在玩小游戏…”、已等待秒数），状态行“等待 xx 玩小游戏…（n 秒）”。
* 玩完后主人的设备发**一条** `RM8C_MINI_RESULT`（`GetResult` 结构的文本），主机排入某一帧，**所有设备在这一帧**用同一个 `rm8MiniRewards` + `applyReward` 发点券、卡片、住院、文字、表情（与单机结束时相同的顺序）；个人最高分只写在主人自己的设备上（本地档案，不是游戏状态）。每台设备都严格解析并核对座位（坏结果 → 电脑逻辑）。
* **主机兜底**：主人断线 / 没有主人 → 立刻发模式 1（电脑逻辑 `aiMiniGame(.., true, false)`：规则随机流在同一帧，**不套进阶规则 B6 低分**——B6 只对电脑 / 托管座位的原有电脑路径生效）；主人一直没玩完 → **5 分钟**后同样处理（`RM8_NET_MINI_TIMEOUT` 可改）。主人的小游戏这时被丢掉并提示“主机已判定这局小游戏的结果”。
* **重连**：主人断线又回来时，主机先决定结果，再给他发 BASE（快照 + 之后的命令，`baseDue`），他追帧时直接拿到主机的结果，**不会重新开始**小游戏。
* 托管座位、电脑座位：原版电脑路径（`aiMiniGame`，含 B6）。卡片规则不变（挖宝 19 不给卡）。
* 修了一个单机也有的错：踩蛋 23 的结果没有写座位（DLL 留给宿主缓冲区），奖励总是给座位 0（`mg_23.cpp` 同 `mg_18.cpp` 写 `seat0`）。

### 7.2 插海盗 21：所有人一起玩
* 任何角色落在插海盗（人类座位；或电脑座位而棋盘上还有人类，同原版）→ **每台设备都显示同一局插海盗**（观战者也看）。每个人类在自己的设备上插自己的剑；电脑座位由小游戏 AI 出手，选择由主机决定并作为命令同步。
* **裁判**（`event_mini.cpp Ref21`，锁步）：DLL 的规则部分（`Barrel_Stab @10001950`、`PickRandomUnusedHole @100010c0`、`StepAngle`、`IsHoleHidden`、`NextTurn @100043e0`、`GetResult @100031d0`）跑在**自己的 MSVC rand 流**上，种子 = 落地那一帧从规则随机流取的数（每台设备相同，等价于主机开局发的种子，但不需要额外的消息）。它决定：海盗是谁、机关洞、每一剑是否插中（与点哪个洞无关，[V]）、电脑 / 超时的洞和转桶方向、结果结构。裁判只在命令执行的帧前进，所以**每台设备的剑序、结果逐项相同**。
* **命令**（`RM8C_MINI_ACT`，带任务号 = 落地帧 + 1、第几剑）：轮到的人类玩家的设备发 `ROT`（每次转一格；回来后才转，所有设备转得一样）、`STAB`（点的洞）、本地 7 秒到时发 `AUTO`（鼠标在洞上就插那个洞，同原版）；电脑座位的 `AUTO` 由主机发——在主机自己的画面走到这一剑（原版电脑回合的 0.7 秒停顿之后，`botDue`）时发；主机画面没在显示时立刻发；兜底 12 秒（第一剑 37 秒，前面有说明框和选海盗约 20 秒）。
* **各设备的画面**（`mg_21.cpp`，`mg::net21()`）：本机玩家的座位 = `human`，其他座位（远程玩家、电脑）= 等裁判的动作；海盗选择的神仙飞行是本地表演，最后飞到裁判的海盗（`onArrive` 改道）；每一剑的结果用裁判的；落后两剑以上时两倍速追；说明框 5 秒自动关（轮次不等它）。画面结束时把自己的 `GetResult` 与裁判的比对写进日志（测试里全部相同）。状态行显示“插海盗：轮到你插剑 / 等待 xx 插剑… / 电脑 xx 插剑”，主机的提示（“xx 不在线，这一剑由电脑来插”）也显示在小游戏画面上。
* **结束**：裁判有结果后，每台设备的画面播完结局（约 4 秒）回到棋盘、发 `DONE`；主机等所有在线玩家（及自己）`DONE` 或最多 15 秒后发 `FINAL`，所有设备在同一帧用 `rm8MiniRewards` + `applyReward` 发奖励（与单机同一路径：插中 +30 / 海盗 −30 住院 3 天、第一剑插中得鑽石卡、海盗赢 (n−1)×30 …）。
* **断线 / 超时**：轮到的玩家不在线 → 主机在自己的画面到这一剑时（最迟 3 秒，第一剑 28 秒）发 `AUTO`；在线但 30 秒（第一剑 55 秒）没出手 → 主机发 `AUTO`（`RM8_NET_MINI_TURN_TIMEOUT`）。玩家回来时照常收 BASE 追帧，裁判按命令重建到当前一剑；画面从头开始、两倍速追上，之后他自己的剑照常由他来插（测试 g21c）；他追帧时主机已经替他插过的剑不会重来。
* 设备不能显示小游戏（数据缺失）时，它的玩家的剑由这台设备自己发 `AUTO`。

### 8.2 PC ↔ 安卓（手动测试步骤）
* `build-android` 编译通过（N4：2026-11-19 23:16），`libmain.so` 的构建哈希与 PC 相同（N4：`fc5687359f91f88c`；N2 时是 `c78ddd2295a61619`），`port/rm8_viewer.apk` 已打包（23:17，v2/v3 签名、zipalign 校验通过）。**没有安装到手机。**
* 准备：两台设备用**同一份源码**构建（PC：`cmake --build build-sdl2`；安卓：`cmake --build build-android` + `python android/build_apk.py`，或提取器打个人 APK），数据用同一版 rm8_extract 输出（否则会被“程序版本不同 / 游戏数据不同”拒绝，提示里有双方的值）。PC 防火墙放行 TCP 47000（或 `rm8_settings.txt` 的 `net_port`）。
* **A. 房间与开局（PC 主机）**：PC `rm8_app.exe <输出文件夹>` → 多人 → 联机对战 → 改玩家名 → 建立主机 → 原版地图菜单选地图和五个选项 → O → 角色菜单加 3–4 个角色，把一个座位的 COM 点成绿色 PLAYER（等待网络玩家）。手机 → 多人 → 联机对战 → 加入游戏 → 输入 PC 的局域网地址（房间浮层里“本机 …”那一行）→ 连接。**检查**：手机上出现同样的地图 / 角色菜单并跟着 PC 实时变；手机点角色头像能换自己座位的角色；手机按 O 准备，PC 浮层“玩家准备 1/1”；再把另一个 COM 也点成等待网络玩家，PC 按 O → 出现“玩家准备不全，是否强制开启？”→ 确认开始。玩几天，两边各点几下聊天短语。
* **B. 反过来（手机主机，PC 加入）**：同 A，手机的地址在房间浮层里；软键盘输入地址 / 名字。
* **C. 后台与重连**：游戏中把手机切到后台 10 秒再切回：不应断线（状态行可能短暂“正在追上主机…”）；切走 60 秒以上：主机显示“xx 断线了，电脑暂时接管”，手机回来后自动重连并拿回座位。手机是主机时切到后台：PC 显示“主机暂时没有响应（可能切到了后台）”，切回后继续。
* **D. 存档续玩**：PC 主机在第 2–3 天 gsys → 存档；两边都退出；PC → 联机对战 → 读取联机存档 → 选该槽 → “等待玩家中…”；手机加入 → 面板显示“已回来”→ 开始。再试一次：不等手机先开始（确认“是否先开始”），过一两天手机再加入 → 回合边界交还座位。
* **E. 外网**：Sakura FRP 等把 PC 的 TCP 47000 映射出去，手机用移动网络连映射地址。
* **F. 小游戏（N4）**：开局时 PC 与手机各一个人类座位，再加一个电脑座位。小游戏格子不好等时，两边都用同样的测试变量开局（PC：命令行环境变量；安卓：`rm8_env.txt`），例如 `RM8_EVENT_TEST=mini18,mini19,mini21` + `RM8_EVENT_SEAT=<手机的座位>`（该座位停下等掷骰时依次落在这些格子上；**两边必须相同**，它在模拟里）。
  1. **单人小游戏在手机上**：手机全屏打开小游戏（说明框点「确定」能开始），PC 上棋盘不动、中间出现“小游戏「快手小厨师」／ xx 正在玩小游戏…”的框，状态行“等待 xx 玩小游戏…（n 秒）”。手机玩完 → 两边同时出现“获得 n 点券”（和卡片），点券数相同。
  2. **单人小游戏在 PC 上**：反过来（`RM8_EVENT_SEAT=<PC 的座位>`，或等自然落地）。
  3. **插海盗一起玩**：落在插海盗后两边都打开插海盗（说明框 5 秒自动关），上方状态行写着轮到谁。轮到手机的角色时手机上出现倒计时，手机转桶（左右箭头）/ 点洞，PC 上看到同样的转桶和插剑；轮到 PC 的角色时反过来；电脑座位自己插。结局（海盗弹出 / 剑插完）两边相同，回到棋盘后两边同时发奖励。
  4. **插海盗里不操作**：轮到手机时不点 → 7 秒后电脑代插（两边看到同一剑）。
  5. **断线**：手机在别人的单人小游戏或插海盗中切到后台 60 秒以上 / 关掉 Wi-Fi：PC 上提示“xx 不在线，这一剑由电脑来插”（插海盗）或“xx 的小游戏改由电脑决定结果”（手机自己的单人小游戏）；手机回来后自动重连、追帧，**不会重新开始**那局小游戏，得到与 PC 相同的结果。

### 9.3 N4：远程小游戏（已完成，见第 7、8.1c 节）
